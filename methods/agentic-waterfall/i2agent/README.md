# i²Agent：独立方法适配

作者仓库固定在 `e546d17848fadbcaf00e4022aa949289d7e7900b`，`source-snapshot/` 是本地独立副本，源文件未经改写；作者仓库当前未找到许可证文件。原方法入口为 `model.py` 的 `i2Agent` 类。由于未找到上游许可证，代码库不分发该副本；需要时运行 `python3 methods/agentic-waterfall/i2agent/fetch_author.py`，脚本按固定提交下载并校验 SHA-256，已有不同文件不会被覆盖。

- `adapter.py` 加载固定哈希的作者类，注入模型调用，保留其五阶段过程。作者的答案驱动重试改为完整候选排列验证；无效输出和请求失败直接记录失败，不自动调用或按隐藏答案修复。
- `agentrecbench_data.py` 将 AgentRecBench 的公开历史、20 个候选投影成作者输入，只保留标题、描述和已发生的评论字段；原工具负责遮蔽目标用户–物品对。无用户指令就留空。
- 原作者会采样未交互物品作为历史选择探测的对照。此适配固定选取不在候选和历史中的一个公开目录条目，仅是未观察的对照，不能当作用户明确不喜欢。评论按公开时间排序，但尚未独立核实官方目标时间和每条历史的严格先后，正式评测前必须完成时间边界核验。
- `data/agentrecbench-amazon-short-task0.json` 是上述公开样本映射，无隐藏答案。字段过滤不是对全部潜在泄漏的证明。
- `live_smoke.py` 把作者的 JSON Schema 转换为当前 API 的 JSON 对象格式、把当前阶段的最后一条提示消息设为用户角色；它保留失败与模型收据。已执行下述两个真实模型冒烟；每一步请求与响应在 `runs/`。

离线检查：`PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s methods/agentic-waterfall/i2agent -p test_adapter.py`。包括 20 候选映射、作者五阶段、拒绝隐藏答案、非法排序、故障不重试、数据字段过滤和传输转换。AgentRecBench task 0 的 9 条历史和 20 候选已用合成模型响应贯穿五阶段；这不是效果实验。

真实模型冒烟：AgentRecBench task 0 的20个候选、MIND 首个公开样本的4个候选分别完整返回。两次各5次实际模型请求，合计17,706 tokens；AgentRecBench 的第一次运行在第5阶段遇到共享额度拦截，随后复用前4个完全一致的请求与成功响应，仅补第5次请求。没有读取答案计算指标，不能据此比较效果。随后 KuaiRand-1K 的一条公开样本（24条 long-view 历史、101候选）也已完整返回；首次排名输出被截断，保留失败后复用前四阶段并将末阶段输出上限从2048提高到4096完成，共6次实际请求、26,872 tokens。KuaiRand 文本补充为后续静态发布，不能声称2022年实时可得。

尚缺正式评分链路、冷启动、连续会话下独立持久状态、KuaiRec 等其他数据集的具体适配；不能宣称完整复现或实验 ready。测试时的模型调用数和工具预算要单独记账；不能把多阶段 i²Agent 和旧版单次调用的 Waterfall 结果直接拼成公平比较。

2026-10-29 KuaiRec 单样本连通检查：使用固定检索对照产生的 100 个真实候选及 20 条历史长观看，5 次实际模型调用均成功，返回 100 个唯一 ID，集合与输入候选完全一致，共 22,732 tokens。记录见 `runs/kuairec-public-example-live-20261029/`。这只是无标签的流程验证；仍需多用户和跨轮状态适配才能做正式实验。

多样本输入：`mind_data.py`、`kuairand_data.py`、`kuairec_data.py` 支持 `--line` 指定从零开始的非空行号；候选检索池如带 `context_id` 会强制核对样本。作者流程读取倒数第二条历史，少于两条正向历史时拒绝输入而非补造。公开输入核查：MIND 1000 行中 967 行满足、33 行不满足；当前 KuaiRand 模型小样本2行中1行满足；KuaiRec dev4 的4行均满足。这些只是输入适用范围，用户已选定主要比较统一使用满足条件的967条，另外33条单独报告不可用情况。

2026-10-29 AgentRecBench 补充：`agentrecbench_batch.py` 接通官方三领域各100条短历史任务和索引，Yelp 缺资料只提供真实 ID。用户允许 Yelp 和 Goodreads 按原文件顺序提供历史，但这不是时间排序；Amazon 使用可见时间排序。分别有96、32、92题至少两条可见评论，其余4、68、8题标记不适用；三个领域各一条真实模型调用成功。`score_agentrecbench.py` 在冻结输出后对 i²Agent 适用子集评分，可同时在同一子集评分 RecAgent；独立报告全100题和适用子集分母，不把二者直接混合。目标发生时间仍未知，不能声称严格因果时间验证。
