# Waterfall 夜间对照方案（2026-11-03）

用户已授权夜间小批量验证，并在效果和可靠性通过后继续既有非 MIND 全量。当前为实验候选版本，不把未选定策略直接改成线上默认。

## 本次明确改动

- 通用核心新增受信任的 `taskInstructions` 接口：适配器输出的数据集 ID 语义、交付数量、证据引用规则进入任务上下文；通用系统提示词没有数据集名或专用阈值。
- 数据集适配器可附加从完整可见个人历史直接计算的统计。KuaiRec：曝光次数、公开目标 `watch_ratio > 2` 次数和比例、原始指标与时长分位数、月份、原记录引用；AgentRecBench：原始评分分布；KuaiRand：原始反馈标志的计数、分母和引用、时长分布。没有跨用户热门分数，也没有隐藏目标。全部原文仍在输入中，重复曝光保留。
- 通用排序指导明确区分曝光与偏好、弱行为与明确反感；用支持证据、相反证据和未知信息比较具体内容；比较全池并复核最强落选项和较弱入选项。无题材配额、无新增硬性检索流程。
- 客户端接受逐任务 thinking 开关并记录实际 reasoning 内容、token 和时间。模式默认保持原设置；实验请求显式指定。
- 换序实验同时保留 `retrieval_rank` 和原检索分数。实际推荐仍输出当前候选索引，由原统一映射还原内容 ID；未引入第二套编号或排名修补逻辑。

## 首轮真实发现与修订

8192 输出 token 的首个真实思考调用全部耗在 reasoning，未输出答案。保留该运行、所有请求和错误；停止新派发后等在途请求结束，没有删掉输入。

新冻结对照统一使用32768输出上限、600秒HTTP等待；旧调用方默认参数不变。移除传输层额外硬编码的8192上限，继续要求显式上限是正安全整数。每轮20次决策、候选100、search-only和既有服务门控保持不变。较高上限增加可用输出空间，不代表每次必然消耗全部额度。官方思考模式可能忽略温度参数，因此记录0.3请求值并披露实际语义，不宣称温度完全相同。

修订后的最大样本真实回执：142188输入token、18657输出token，其中18183 reasoning token，单次请求152434毫秒，完整合法10项交付。这里只证明接入及交付可用，不代表效果提高。

## 固定实验与后续门槛

同8个开发用户、完整历史、相同100候选：control；+适配说明；+思考；+通用证据比较；+个人统计，各8题。control和统计组各增加8个逆序任务，共56题。逐因素比较；不挑最好排列覆盖原结果。

随后固定候选重复检查与完整获取流程分开。先在开发样本比较当前/选择版本/观察返回后补搜策略，保持总100候选；再在本轮未用于选择的dev32–39上对照。其他数据集预定同题复验：AgentRecBench三域各4题、KuaiRand按ID前4个既有测试任务、SimBench同一用户连续5事件。它们属于诊断复验，不能据此声称所有领域显著提升。

只有推荐指标、未参与选择的开发用户和跨数据集可靠性支持扩展，才准备新冻结2256题全量：KuaiRec1129、KuaiRand617、AgentRecBench300、SimBench210。MIND保持暂停。全量KuaiRec使用完整原始big历史，旧准备版本不复用。所有历史结果、失败及费用保留。

## 新增通用排序段落的中文译文

在选择物品前，形成与证据强度相符的用户理解。区分用户接触或消费了什么，以及如何回应。频繁曝光表示熟悉，不等于强烈偏好。比较重复参与、弱回应和明确负反馈；按数据来源说明理解指标，低行为值不自动等于拒绝。比较相似内容的反馈，并考虑形式、时长、时间和环境。样本少时保留不确定性，相反观察应降低信心。

任务上下文提供统计时，用次数、分母、分布、时间范围和引用核对直觉，并结合完整原始记录理解内容的子主题、作者、用途和表达方式。统计是观察结果，不能直接证明因果偏好或保证未来结果。记忆应保留这些区别和不确定性，而不是把出现过的类别全写成强兴趣。

在证据能够区分候选的粒度上比较。对于有竞争力的候选，判断哪些历史观察支持它、哪些削弱匹配、内容具体提供什么，以及还有什么未知。类别匹配只是起点，应继续比较具体属性、用途、形式、深度和情境。某个属性的强证据不能自动推广到所有同类物品。先把这些区别与任务目标联系起来，再决定次序。

比较完整候选池，包括不同查询、来源和后到的内容。展示位置、数字编号和到达顺序只是记账信息。保留原检索上下文和分数，但区分查询匹配与个性化适合程度。用相同标准评估池中不同部分的候选。相似候选也需要有依据的次序，默认保持或反转输入顺序都不能解决不确定性。

提交前，用最强的落选项检查较弱的入选项，重新考虑缺乏支持的位置。确认顺序反映目标和证据，而不是阅读顺序。无法可靠区分时保留不确定性，不编造个人理由。推荐动作引用实际使用过的可见记录或工具回执。先选择最匹配的内容，再根据任务需要考虑多样性。

完整实际英文提示在唯一维护核心 `demos/agentic-feed-site/lib/waterfall/waterfall-core.mjs` 的 `SYSTEM_PROMPT`。其余段落沿用上一版。英文请求与原始响应逐次存档。

## 最终选择与发布（2026-11-03）
选择 adaptive：完整个人历史与描述统计、明确证据比较、根据返回继续检索、DeepSeek-V4.1-Flash-1017 开启思考。独立8人 NDCG10 0.01064→0.25117，Recall10 0.000926→0.017938；候选召回0.04337→0.03930，不能把收益都归于检索。跨域21题新方案全严格成功，旧方案1次错误引用保留零分。各组汇总不下降，但 Yelp与KuaiRand@10仍0；Sim共同池仅1/2级弱相关、Hit20为0，不能用较高归一化分数声称推荐有用。小样本只支持继续全量验证，不支持普遍有效结论。
默认英文SYSTEM_PROMPT逐字提升为本次已验证adaptive提示，运行决策代码不变。实验与Demo共用流式解析，保留原始reasoning、usage、未完成流。Demo输出上限8192→32768、HTTP等待60→600秒；线上多方法共同上限也为32768，Waterfall显式开启支持该参数的提供商的思考，其余方法思考设置不变。各数据集统计仍在适配器中，Demo不伪造缺失的观看指标。实际线上非日期模型别名与1017测试服务的差异保留，不声称模型版本相同。
这些是显式配置变更，不是截断或补齐。独立用户平均17.1→203.1秒，效果优先但时间明显增加。全量保留2256原任务、100候选与search-only边界；Yelp源数据缺失、Sim工具来源与需求不匹配均计入结果，不能给Waterfall单独增加来源。
