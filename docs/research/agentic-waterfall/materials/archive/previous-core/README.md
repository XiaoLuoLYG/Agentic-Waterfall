# Waterfall 研究：从这里开始

> 历史材料：保留当时内容，不作为现行方案。当前以 [研究主方案](../../../01-研究主方案.md) 和 [输入输出与数据流](../../../02-输入输出与数据流.md) 为准。

**目标：定义 Agentic Waterfall Feed，让 Agent 贯穿获取、推荐和交互式更新，持续提供用户愿意看的内容。**

当前主贡献保持三项：范式定义、统一 Agent 框架、端到端数据与评测。数据评测约占一半。RecBot、ClawRec、MARS 用于定位差异和吸收方法。

## 只看这四份

| 顺序 | 文件 | 解决什么 |
|---|---|---|
| 1 | [逐步例子](../../../02-输入输出与数据流.md) | 每一步用户操作、给 Agent 的数据、完整 JSON 输出、并行工具调用和实际结果 |
| 2 | [怎样评好坏](../../references/evaluation-details.md) | 下一条盲选、整段续用选择、NDCG 演算、数据怎样采 |
| 3 | [输入输出约定](../../../02-输入输出与数据流.md) | 实现和采集都使用的字段及动作定义 |
| 4 | [完整机器记录](../../example/episode.json) | 同一个例子的完整输入、原始/解析输出、调度组、回执和状态 |

例子用内容名称作可读标识，例如“手机跟拍足球：四个动作”，不要求记编号。全部内容与输出为作者示例，不是实验结果。

## 已完成与接下来

- 完整例子有 8 次决策、两路实际并发的本地模拟来源调用；已有回放与输入边界检查。
- 主评测改为“选哪条 / 继续用哪个系统”；1–5 分只保留为可选补充。
- 下一步把同一输入下不同系统的下一条建议做成匿名选择题，先检查题目能否让真人自然作出选择。
