## 一页结论

**[判断] 这个体验适合作为论文的叙事中心，但不能单独算原创方法。可以继续以 ACL 主会长文为目标；当前最缺的是可以与强近邻区分的机制，并非仅缺实验。**

普通人能理解的中心句可以保留为：**用户想说时，能直接告诉信息流怎么改；不说时，系统也能从实际浏览中继续理解他，并让后续内容跟上。** 这里的系统行动可以只是调整未展示内容、补充获取或更新当前理解，不要求主动提问、弹通知或把用户引向预设商品。

| 要回答的问题 | 独立结论 |
|---|---|
| 有类似工作吗？ | **有直接近邻。** RecBot 的 Interactive Recommendation Feed 就是边刷信息流边用自然语言改推荐，并融合隐式历史；ClawRec 已把行为、聊天、状态、跨源获取、排序和反馈连接起来。不能把二者都描述成只会聊天或只会静态排序。[RecBot v2 §§2–3](https://arxiv.org/html/2509.21317v2)、[ClawRec v1 §2](https://arxiv.org/html/2607.23779v1)。 |
| “不说时也自己判断”是否补足了原创性？ | **没有自动补足。** 根据行为适应是推荐的基础能力，边浏览边自主探索也有早期先例。可以研究的是：用户发言稀疏时，两种证据如何共同改变当前任务与下一步行动，而不让弱行为抹掉有效要求。 |
| 能否作为全文主线？ | **能。** 它清楚说明使用情境、为何需要语言、为何不能只测一次排序。主线不必缩成消歧、主动问答或推送。 |
| 怎样成为完整研究问题？ | 研究“**用户主动纠正与系统依据行为的适应，如何持续共同约束获取、排序和状态修订**”。重点包括任务形成、细化、改变、完成和保持原样；必须说明何时改、改哪里、哪些旧决定受影响。 |
| ACL 主会潜力与当前成熟度？ | **问题有潜力；方法尚未成熟。** 如果同信息的强联合系统也能做得一样，Waterfall 不能以“首次统一”或“专门控制器优越”立论。若提出清楚机制并产生可信、可复用的发现，冻结模型和系统方法本身不是障碍。 |

**[提案] 推荐只抓两项主张：**第一，一套处理语言与行为的持续联合适应方法，具体到证据的作用范围、状态修订和受影响行动；第二，证明收益来自这种联系，而非仅仅多给了语言输入、更多历史或更强工具。真人连续交互数据作为补充贡献，记录实际展示与后续反应，支撑并开放这个问题。

**当前最优先的工作：**写清一页可执行规则，解释同样一段“发言—浏览—再发言—沉默浏览”，Waterfall 与简单融合、ClawRec 适配版及同动作通用 Agent 会因哪条机制产生不同决定。若说不清，先不扩大实现与采集。

沉默只是没有语言，不是新的偏好证据；“沉默期间发生的观看、收藏、跳过等行为”才是输入。反过来，用户说了一句话，也不必产生聊天回复；可以直接改变后面的内容。

### 2.1 两个最容易误读的结论

**[事实＋判断] RecBot 不是只有口号或静态聊天界面。** 其形式化输入已包含显式偏好与隐式历史，原文也把探索浏览、用户对具体推荐的语言反馈作为场景。它将 IRF 称为 reactive，且离线多轮每轮都收到语言反馈。由此只能说：**本次所读证据没有把“长段无发言时怎样更新任务、何时改行动”单独作为已验证机制。** 不能说它完全不读行为、无法继续推荐或不会处理兴趣变化。论文自身对传统对话推荐的概括也不应被照抄成整个领域的能力上限。[RecBot v2 §§2、3.5.2、4.1.2](https://arxiv.org/html/2509.21317v2)。

**[事实＋判断] ClawRec 已经迫使差异下沉到具体决策。** 它不只合并日志：任务会冷却、过期或受抑制，显式上下文可修订记录，获取和列表选择面向当前任务。因而“语言＋行为＋任务状态＋跨源获取＋排序”不是一个尚无人连接的框架。所读论文也未提供本题真人自然发言与沉默交替的独立证据；这留下的是研究与验证空间，不能推成方法能力不存在。[ClawRec v1 §§2.3–2.5、3.3](https://arxiv.org/html/2607.23779v1)。

### 2.2 动态工具与混合主动权的必要边界

**[事实]** [ToolRec v1 §3.2](https://arxiv.org/html/2405.15114v1)已由代理根据历史、当前候选和工具返回选择检索、排序或结束；内部代理满意不是真人曝光反馈。[ChainRec v1 §4.1、Algorithm 1](https://arxiv.org/html/2602.10490v1)已有观察—选择工具—执行—更新共享记忆的循环，但主要为给定候选获取证据后排序，并训练规划器。两者足以排除“动态行动＋结果回读”本身是独有方法的说法；不必为这次体验评估再穷尽所有工具 Agent。

**[事实]** 早期 [Letizia，IJCAI 1995 原论文](https://www.ijcai.org/Proceedings/95-1/Papers/119.pdf)已经根据浏览行为在后台探索链接、动态准备建议，且不要求用户先声明目标；它没有自然语言理解能力。[Horvitz，CHI 1999 原论文](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/11/chi99horvitz.pdf)讨论自动行动与用户直接控制的配合，以及不确定性、行动时机、可中止服务和持续观察。

**[判断]** 这些不是今天完整系统的等价基线，却清楚说明：混合主动权不只是一人问一句，也不意味着代理必须主动追问。Waterfall 可以使用这一思想，不能声称首次发明它。

## 3. 一个完整、普通人能理解的故事

**[提案；以下是说明设计的虚构过程，不是已运行案例。]**

小林晚上随手刷摄影内容，点开了相机比较，也收藏了一段拍运动的演示。系统可以暂时认为他对摄影感兴趣，继续给一些相关内容；这还不足以断定他要买相机，更不能把一个品牌写成长期喜好。

后来他说：“相机已经借到了，周末想拍孩子踢球，先告诉我怎么设置，别再推荐买器材。”这句话改变了当前事情：从宽泛摄影探索变成运动拍摄准备。接下来的信息流应该出现跟焦、快门和现场设置。如果现有内容里已经有这些，只需调整后面的顺序；没有才去找。

随后十分钟他不说话。他反复看跟焦演示，跳过重复的开机教程，收藏了一张设置清单。系统可以据此逐步增加跟焦和可照做的内容，同时保留“不要买器材”的要求。即使他顺手点开了一篇镜头文章，也不能只凭这一次点击就恢复器材购买推荐。若行为仍不清楚，继续提供当前任务可用的内容也是合理行动。

小林又说：“基础设置我会了，我主要是不知道孩子跑出画面后怎么重新跟上。”这次语言让前面的浏览有了更准确的解释。系统需要调整未完成的问题，停止反复找基础设置，转而提供取景、追踪和重新捕获主体的内容。一个较早发出的“相机入门”搜索此时才返回，也应按新要求重新判断哪些结果仍有用。

最后他说：“明白了，周末试试。”系统可以记下当前讲解告一段落，之后的摄影浏览再提供新证据；它不能把“看完了”写成“已经拍成功了”。整段过程中，小林不需要不停打字，也不必被追问。他说的时候能纠正方向，不说的时候仍能继续浏览。

**[判断] 故事中的交互形式、指令解析、行为个性化、任务记忆及工具获取都已有先例。** 值得研究的联系是：一条语言要求怎样改变随后行为的含义，随后行为又怎样在该要求的有效范围内推进任务；这种修订怎样同时影响还在执行的获取、未展示内容和用户状态。不能预设 RecBot、ClawRec 或通用 Agent 在故事中一定失败，真正的差异要由同信息比较发现。

## 4. 推荐问题与主贡献：保留完整范围，把关键联系写实

### 4.1 推荐研究问题

**[提案] 当用户在持续浏览中偶尔用自然语言纠正系统时，怎样联合利用语言与实际行为，持续决定下一步获取什么、展示什么、保留或修订哪些理解，使内容跟上需求进展，同时避免过度推断和过时要求继续起作用？**

这涵盖探索、明确任务、补充要求、无发言适应、任务改变和任务结束；消歧只是一种情形。系统无需知道用户隐藏在心里的唯一真意。证据不足时保留未知、保持当前内容也应是合格结果。

### 4.2 主方法主张一：把两种证据变成有范围的修订，并传到行动

**[提案]** 在当前统一控制器上，优先明确以下关系，形成一套可替换的机制。无需增加新模型或多个 Agent。

| 环节 | 至少写成什么规则 | 它对应的研究难点 |
|---|---|---|
| 解释新证据 | 每次解释说明对象、时间、当前任务、依据；区分原话、行为与推断。语言中的明确禁令只在其适用范围内成为约束，普通愿望不能全部硬化 | “别再推荐器材”与“我有点想看看”不应使用同样强度；点击也不是一句完整需求。 |
| 联合修订 | 新的明确纠正可以替换冲突解释；行为可细化未确定的部分、修订已有行为推断，但不能仅凭一次点击撤销仍有效的明确要求。没有新增证据不自动更新 | 两个渠道不是把分数相加就结束：话语改变行为解释的上下文，行为补充没有说出的进展。 |
| 指明影响范围 | 每次修订关联受影响的任务、需求、计划和候选判断；保留无关偏好。任务结束不等于删除兴趣 | 不能一边改了画像，另一边继续按过时目的获取和展示。 |
| 选择获取、重排或保持 | 依据当前接受状态判断现有内容能提供什么支持；已有合适内容先调整，缺少所需支持才获取；证据不足或变化不影响下一步则保持 | 不是每次行为都大改列表，也不是必须等一句新命令才能改变内容。 |
| 回读实际结果 | 返回结果按当前要求复核；旧查询结果可以被复用，但不能因当初查询过就获得永久展示资格。工具失败只改变执行记录 | “系统搜过”“用户看到”“用户学会”不能混成一个事实。 |

**拟议增量是这些关系对连续交互的作用，不是状态字段或 JSON。** ClawRec 已有很多基础关联，InterQuest 已有知识范围，RecBot 已有局部冲突更新；因此上述完整规格仍是候选方法，尚不能宣称首创。若强联合基线自然实现相同决策，就应承认这一形式化主要是可靠实现和研究组织，并继续判断是否还有独立方法价值。

对“何时动”采用一个最小默认：在用户语言、新行为批次或工具返回到来时允许重新判断；本轮可以选择不改。先把**重新判断机会**与**实际获取/重排/写状态**分开。固定合理检查点已足以研究行为驱动适应；只有确实提出并验证更好的触发选择，才额外声称“学会时机”。不必把信息流研究扩成通知调度。

### 4.3 主证据主张二：证明是联合机制有用，并解释何时有用

**[提案]** 论文应回答：同样看到语言和行为时，显式的修订与行动联系是否比简单合并、成熟流程和强通用规划更好？有价值的发现可能是：语言纠正让后续行为得到更合适的解释；行为让稀疏命令之间的推荐继续推进；范围传播减少旧任务获取与无关偏好误改。也可能发现简单融合已足够，或主动调整常常过度。

这是一项待证实的实证主张，不应先写成三项提升。它比“各模块移除后都变差”更有解释力，因为所有方法都可以拥有好用的解析器、记忆、工具和排序器。

### 4.4 真人数据仍作补充贡献

**[提案] Waterfall-Loop** 保存真人在同一浏览过程中的实际曝光、自然发言、点击/观看/跳过等操作、当时可见内容、系统状态修订及实际执行结果。重点补上**用户没有发言的区间、纠正前后及未发生需求变化的区间**，而不是只收集漂亮口令。

真实数据应支持需求理解、状态修订范围、行动适切性和连续有用性的研究。状态正确性可以来自原话、可核对事实和结束后有限确认；不能用事后的新目标倒填过去的唯一意图，也不能把没有选择的内容全部标成讨厌。真人、研究者安排的任务/条件、生成内容和模拟反馈分别标记。

24–40 人足以规划有边界的探索与比较，但人数本身不证明统计充分、长期个性化或工业规模。公开一条真人轨迹也不能提供其他策略未展示内容的真人反应。数据应保持独立说明和复用价值，定位仍是方法的补充，而非在方法弱时自动换成“数据主贡献”。

## 5. 最小关键比较：把输入增益和机制增益分开

**[提案]** 先搭共同底座：同一个冻结模型、原始证据格式、内容语料与获取权限、状态容量、候选摘要、解析/评分组件、执行错误恢复，以及合理的展示稳定性。成本和等待时间是公平约束，不能让 Waterfall 独享更多查询或预看未来。

| 条件 | 可见信息与决定方式 | 能回答什么 |
|---|---|---|
| **话语驱动** | 使用相同初始背景与用户原话；后续不使用新增隐式行为来修订目标。明确命令后可获取、排序、更新状态 | 新增行为在发言间隙是否有用；不能用它证明 Waterfall 的专门机制优于强系统。 |
| **行为驱动** | 使用相同初始背景、曝光和实际行为，不读后续自然语言；保留合理的会话适应 | 自由语言究竟补了什么；它不知道的新命令导致的错误属于信息缺失。 |
| **简单融合** | 两类原始输入都可见；同一解析器提取要求和行为摘要，明确要求优先，其余按开发阶段选好的规则合并，再共享给获取和排序；允许基本任务时效与重试 | 多一种输入加正常工程处理是否已经够用。不能故意做成每轮清空状态或让点击覆盖明确禁令。 |
| **同信息的强联合系统** | 连续运行的 ClawRec 适配版，以及拥有同状态、同动作、结果回读和重规划权限的通用 Agent；按各自完整策略使用两类输入 | 与最近的完整方法及强通用能力比，Waterfall 的关系设计是否有独立价值。按论文适配必须披露差异，不能冒充官方复现。 |
| **Waterfall 机制** | 全部共同能力；额外采用前述有范围修订及其向获取、候选和状态的显式传播 | 检验专门机制，而非更多信息、不同模型或更强工具。 |

话语/行为驱动是输入对照，简单融合和强联合系统才是方法对照。**Waterfall 胜过两个单渠道条件，只能先说明输入互补；不等于已经证明新的联合方法。** 也不要用一项差值算术直接宣称存在机制协同。

最小机制替换做两项即可：其一，保留全部两类原始证据和共同状态字段，但把专门的联合修订规则替换为合理融合/通用判断；其二，保留相同修订结果，把显式影响传播替换为每轮重读最新状态并重规划。第二项必须允许对照合理重算，不能故意保留旧状态制造错误。如果重算同样好，专门传播可能只剩效率或工程收益，应按实际结果写。

**两层证据分工：**

1. **相同历史前缀的诊断。** 对语言纠正、无发言进展、信号冲突、明确无变化、任务完成与晚到工具结果，比较状态和下一步动作。各方法只用前缀当时可见信息；从而定位差异发生在哪里。
2. **各自真实曝光后的连续交互。** 真人体验 Waterfall 与开发阶段选出的强对照；评价在可比浏览机会内获得的有用独特内容、要求违背与错误状态修改，另看需求变化后多久恢复有用推荐。后续用户反应随策略分叉，不能把同一条旧点击轨迹回放给所有方法当真实效果。

不要为了证明“无发言能力”强迫所有人沉默，再宣称这是自然行为。可以有单独标记的受控无发言条件，但主结果应保留自然发言频率、退出、没有反馈和稳定任务。点击/停留是在线输入，不可直接当满意真值；评价标签也不回传控制器。若任务已经完成，少刷几条可能是好结果，U@40 等指标要保留这一解释边界。

## 6. 应吸收什么、创新归谁

| 现有优点 | 推荐采用方式 | 不能记到 Waterfall 头上的创新 |
|---|---|---|
| RecBot 的正负、软硬指令及局部冲突修订 | 放入共同解析层，保留原话、对象与作用范围；所有完整对照可用 | 首次自然语言控制信息流、首次融合语言与历史。 |
| ClawRec 的证据关联任务/偏好、时效、来源功能及反馈关联 | 作为状态和获取的强起点，正面实现完整对照 | 首次把行为变状态、首次任务生命周期、首次连接跨源获取和排序。 |
| InteRecAgent 的即时 `expect`、候选总线、执行轨迹与反思 | 复用状态与工具底座，保留工具失败后的修复能力 | 首次区分即时要求与长期喜好、首次工具回读。 |
| InterQuest 的知识适用范围与知识正确性分开核查 | 借鉴范围表达和本人核查思路；不必引入主动问答 | 首次动态维护偏好范围；LLM 自报置信度也不能直接当校准概率。 |
| ToolRec / ChainRec 的逐步工具决策与终止 | 构成强联合 Agent 的能力标准；冻结适配须说明并非训练版复现 | 首次动态规划或“输出动作而非文字”。 |
| STEPS 及经典混合主动权对行动时机的区分 | 借鉴“何时评估”与“执行什么”分离；本轮不引入通知工具 | 首次主动系统、首次可以不行动、首次人机共同掌控。 |

**[判断] 可争取的创新归属是具体修订—行动关系及其产生的新知识。** 现有成熟能力可以大方采用。没有必要为显得原创而重做解析器、排序器或训练一套策略，也没有必要宣称定义了一个新领域。

## 7. ACL 主会潜力、当前成熟度与收缩条件

**[事实]** [ACL 2027 CFP](https://2027.aclweb.org/calls/main/)要求有实质、原创的计算语言学/NLP 研究，也接纳资源和负面发现等贡献；范围包括交互、人本 NLP、信息检索与 NLP Agent。[ARR Review Form](https://aclrollingreview.org/reviewform)分别考察主张的科学支持、方法和评估可靠性，以及研究是否给读者带来有价值的新认识。官方没有要求必须训练新模型，也没有给某个参与者人数或架构形式保证录取。

**[判断] 有主会竞争潜力的版本：**语言不是附加输入框，而是改变后续行为理解和可执行决定的核心；方法对这种联系给出可复现规则；同信息强比较揭示收益与失败；真人轨迹证明真实使用中的意义。整合方法可以有贡献，但必须让读者获得超出“把聊天接到推荐”的知识。

**[判断] 当前版本：**体验方向清晰、研究范围合理，完整方法及证据尚不足。最接近的方法不是只有较窄的排序器，ClawRec 与 RecBot 需要正面处理。即使本报告的建议全部写成代码，也不能提前判定达到主会水平；具体方法是否超过成熟组合仍未知。不能提供可信录用概率。

**[提案] 最优先补这三件事，按顺序做：**

1. 写出一页可执行的联合修订与行动规则，含保持、任务结束、证据冲突、工具失败；指出相对 RecBot 与 ClawRec 多出的关系。不要先增加更多模块。
2. 用静态轨迹审查与同信息强方案逐项对照，明确可能同样成功的情形和真正可能分歧的情形；若只剩“提示词写得更好”，如实重估主张。
3. 方法明确后再实现、先导和冻结真人协议。未来采集应包括自然的发言与沉默交替，不要求每个人按同一脚本展示漂亮转折。本轮不执行这些实验或招募。

| 如果得到的结果是…… | 必须收缩什么 | 可以继续保留什么 |
|---|---|---|
| 简单融合与 Waterfall 相当 | 撤回专门联合控制是收益来源、必须采用复杂机制的主张 | 两类输入的互补性、简单融合适用条件及数据；重新判断这些发现是否足够重要。 |
| ClawRec 适配版或同动作 Agent 追平 | 撤回通用流程无法做到、独有整体框架优越的主张 | 完整任务评测、可用实现、已有方法的能力与局限发现；不自动转成强资源论文。 |
| 只在新增语言命令后提高 | 收缩“沉默时持续理解进展”的主张 | 指令控制与纠正收益。 |
| 只提高当前列表，状态与获取没有贡献 | 收缩全链路联合控制贡献 | 实际有效的排序或解释机制。 |
| 频繁调整损害稳定任务 | 收缩主动适应普遍有益的主张，修改保持/更新边界 | 何时不应行动的发现；不能只报发生变化的子集。 |
| 仅模拟有效，真人证据不足 | 不声称改善真实用户体验或任务完成 | 限定模拟协议下的结果及模拟与真人的差距。 |

不能把“没有显著差异”直接说成等效；要看用户/轨迹级不确定区间及能排除的实际差异。也不能因方法追平就把数据改称主贡献，并跳过对资源新意与质量的评估。

## 8. 核查边界

本次独立读取了七项主近邻的方法/评估相关原文，补核 ToolRec、ChainRec、混合主动权经典来源及 ACL/ARR 官方页。RecBot 的发表归属由作者组确认，方法依据 arXiv v2，未逐字比较 ACM 最终版本。iAgent 正式 PDF 抓取不稳定，方法与实验细节以可读的 arXiv v4 核验，发表归属以 ACL Anthology 为准。Letizia 使用会议原论文的索引全文片段，未逐页检查其全部实现与实验。

本次只新增本报告；未修改正文、产品或 A 图，未运行作者代码、实验、模型评测或招募。未穷尽所有相关工作；也未独立复核作者线上结果或完整数据质量。主要风险是：完整设想与已有能力重合较多，拟议机制最终可能被简单融合或强联合系统追平，届时需要按上表收缩主张。
