# Waterfall v0.3：独立 ACL 长文研究评估

> 历史材料：保留当时内容，不作为现行方案。当前以 [研究主方案](../../01-研究主方案.md) 和 [输入输出与数据流](../../02-输入输出与数据流.md) 为准。

评估日期：2026-10-26。对象是当前 v0.3 研究提案；不是对已完成论文的正式同行评审，也不是录用预测。下文用 **[事实]** 标识当前文件或一手来源所述内容，用 **[判断]** 标识本报告的分析，用 **[提案]** 标识尚未实现、尚未验证的建议。

## 一页结论

**[判断] 可以继续把 ACL 主会长文作为研究目标，但当前版本还没有定义出足够清楚的方法增量，不能判断为“方案已够，只差实验”。** 三件事需要分开：

| 维度 | 独立结论 | 主要原因 |
|---|---|---|
| 研究潜力 | 有，值得继续做完整搜推研究 | 连续行为、自然表达和任务进展如何共同改变信息获取，是语言理解与交互决策问题；真实反馈能揭示静态排序看不到的错误。 |
| 已定义的方法增量 | 目前不足 | v0.3 定义了清楚的输入、输出和执行边界，但核心仍是通用 Agent 循环的推荐实例。ClawRec 已有近乎相同的整体范围；ToolRec、InteRecAgent、ChainRec 又覆盖动态选择、执行回读和重规划。 |
| 当前投稿成熟度 | 尚不适合以完成的实证方法长文提交 | 首先缺相对强近邻可区分的决策机制，其次才是该机制的实现和证据。旧 TeX 的候选数量规则也尚未与 v0.3 同步。 |

**最优先补的不是更多模块，而是一项方法定义：任务发生变化时，哪些认识应修订、哪些获取计划与候选判断因此失效，以及为何选择获取、重排或保持。** 这项机制必须能写成可执行规则，并能在保留同样信息、状态和成熟组件时被替换掉。

推荐保留“连续交互驱动统一搜推”为主线，具体研究**任务进展、状态修订与后续行动之间的依赖关系**。真实连续交互数据仍作补充贡献，支撑并检验这个机制。无需把整篇缩成消歧，也不建议通过增加多代理、训练或跨用户图来制造复杂度。

24–40 名参与者、每人 45–60 分钟，是开展有边界的人机交互研究的可用起点；不是已经足够的统计保证，也不是长期个性化证据。如果共享状态的成熟组合或同动作通用 Agent 追平，必须撤回“专门统一控制带来收益”的主张，不能靠换标题或称作数据论文自动保住主会结论。

## 1. 评估对象和事实边界

**[事实] 本次从以下当前文件读取研究定义：**[贡献一页纸 v0.3](2026-10-26-waterfall-contribution-onepager.md)、[方法设计 v0.3 的附录前主体](2026-10-26-waterfall-method-differences.md)、[当前研究计划](2026-10-20-waterfall-unified-architecture-paper-plan.md)、[旧 TeX](../../../../../paper/acl-2027/official-template/acl_latex.tex)。[2026-10-20 实现审计](2026-10-20-manuscript-implementation-audit.md)只作为带日期的静态原型证据；本次没有重新审计当前产品分支。

v0.3 的对象是：授权的连续操作及内容上下文、自然表达、已有状态、当前候选与执行结果进入冻结 LLM；模型提出状态修改和可执行动作；执行后的真实结果及后续行为进入下一轮。旧的“歧义对照获取”附录不是当前主方法；旧稿的数量门控也不能自动视作已经确定的新控制器。

现有原型中的受限记忆/查询更新，不等于上述完整控制器已实现。计划明确尚未完成控制器、实验、招募或数据采集。本报告没有把案例、历史组件结果或原型存在当作有效性证明。

既有文献笔记用于定位待查来源；以下关键能力判断重新读取了论文正文或作者代码。没有把此前“认可方向”的表述当作独立证据。

## 2. 按 ACL / ARR 官方标准怎么看

**[事实]** [ACL 2027 官方 CFP](https://2027.aclweb.org/calls/main/)要求 substantial、original 的计算语言学/NLP 研究，范围包括交互系统、人本 NLP、信息检索和 LLM Agents for NLP；也允许资源、负面发现等贡献类型。长文正文上限为 8 页。[ARR Review Form](https://aclrollingreview.org/reviewform)分别考察科学主张的支持程度、方法与评估可靠性以及研究价值；主会判断还可以考虑新颖性和影响。官方没有“必须有新模型”“必须多少参与者”或“某种架构必然够主会”的规则。

| 评估维度 | 对当前工作的判断 | 完成后有价值的证据 |
|---|---|---|
| ACL 相关性 | **成立，但不能只凭使用 LLM。** 核心应是带上下文的行为/语言解释如何改变可执行搜推决策；如果论文只分析接口、吞吐和来源数量，NLP 贡献会变弱。 | 任务转换、指代对象、否定与纠正、暂时要求和已完成事项怎样影响行动；哪些语言/历史条件导致方法成功或失败。 |
| 贡献与研究价值 | **问题有价值，概念首创不成立。** 统一四环节、冻结模型、JSON 输出和多轮适应均有先例。系统整合仍可能成为贡献，但需产生此前组合难以获得的能力或可复用发现。 | 一项明确机制，加上其在真实连续交互中的收益和边界；或足够重要、可信的实证发现。不能仅靠组件逐个有用。 |
| 技术充分性 | **接口规格有进展，决策方法未定。** “模型一起决定理解与动作”没有解释哪些输入关系改变动作，也未给出可复现的选择与修复规则。 | 明确状态转移、动作前提、结果回读、失败路径和终止条件；别人能按规格实现，不依赖作者临场修改提示。 |
| 证据与效度 | **当前无主张成立的实证依据，但这不是唯一缺口。** 只补一般效果表，仍可能证明的只是更多上下文、更好的工具或更强评分器。 | 与完整强对照比较、机制替换、独立真人有用性判断、失败分析；区分用户反馈、工具观测和评价标签。 |
| 数据贡献 | **有潜在补充价值，价值来自记录什么及能检验什么。** 人数或“真实”二字本身不够。 | 真实曝光及随后反应、任务变化的可靠确认、清楚的数据来源和可复用协议；不能让合成目标混入真人事实。 |

**[判断] 相关论文可以校准范围，不能提供录取公式。** [Tunable LLM-based Proactive Recommendation Agent](https://aclanthology.org/2025.acl-long.944/)确为 ACL 2025 主会长文，研究实时反馈下的多步推荐与可训练策略；[MemRec](https://aclanthology.org/2026.acl-long.2061/)确为 ACL 2026 主会长文，明确提出协同记忆及记忆管理与推荐推理的分工。这说明推荐 Agent 与架构研究可进入 ACL；不能推出 Waterfall 只要同样使用 Agent 或补几组实验就满足标准。两篇在这里用于主题/贡献形式校准，不作为本报告对其全部实验质量的背书。

### 当前最主要的五项问题

1. **可能致命：核心差异被已有方法覆盖。** 如果最终方法仍只是“读历史—更新状态—选工具—看结果”，那么方法主张的基础不足；更多实验不会自动创造一个不存在的差异。
2. **主要：尚未规定从理解到行动的机制。** 相机例子说明了想要的行为，没有规定在不那么明确的真实场景中如何实现。需要定义可以被替换、被检验的决策关系，而不是让解释文字充当算法。
3. **主要：成熟组件会造成收益归因混淆。** 新解释器、候选摘要、来源角色、排序器只给 Waterfall，比较就变成能力不等价；只赢旧原型或单独的重排器不能证明统一控制。
4. **主要：连续评估容易把已记录轨迹当成新策略的反馈。** 用户看见不同内容会作不同反应，离线重放不能直接回答另一策略的真实结果。过于整齐的目标切换脚本还可能奖励提示匹配，而非连续理解。
5. **主要：稿件、方法和证据处在不同版本。** 旧 TeX 的可执行数量规则比 v0.3 具体，却不是现主线；原型又没有完整控制权。若不逐项同步，读者无法辨认研究究竟验证了哪个系统。短时研究也不能支持跨周/月的“长期学习”。

### 3.2 连续评测和数据不能混为一谈

**[事实]** ClawRec §3.3 用先前生活事件及当前事件前缀推断隐藏的下一步；隐藏行为是语义参考，不要求同一 URL。RecBot §4.1.2 已有最多五轮、针对当轮 top-1 的模拟反馈，并在第三轮切换目标；不能称 Waterfall 首次有曝光相关多轮。MARS §4.1 顺序接收历史行为，但测试仍是最后一个正例加九个随机候选。这些都不是“让各策略的真人在看到不同内容后自然继续”的同一种证据。

**[事实]** [PersonaMem-v3 论文 v2，2026-10-07](https://arxiv.org/html/2608.21381v2)及[作者数据卡](https://huggingface.co/datasets/bowen-upenn/PersonaMem-v3)已经覆盖跨应用行为、自然语言推荐控制、偏好生命周期和主动行动。数据卡明确其真人日志底座经过重采样并生成模拟数字生活。因此，“跨平台＋行为＋语言＋时间”不足以区分 Waterfall 数据；**研究对象实际看到了什么、随后如何真实行动**，才是值得补充的关键记录。

**[判断]** 真实反馈资源有价值，但离线发布一条真人轨迹仍不能提供所有未展示策略的反事实反应。公开数据可以支持状态理解、动作适切性、固定候选诊断和已记录策略下的分析；对新控制策略的长期收益，仍要新交互或明确受限的估计假设。

## 4. v0.3 是否只是 Agent 循环？

**[判断] 就目前抽象层级，是。** 把经历作为观测，把状态修改/检索/排序作为工具，把返回作为下一轮输入，可以直接写进通用工具 Agent。v0.3 的重要进步是把权限、可见信息和预期用户行为说清楚；这属于研究规格进展，尚不自动成为新的决策算法。

“一个控制器”只说明软件组织。若同一个模型通过两次调用做同样决策，或两个模型通过同一个状态完成同样行为，控制器数量没有解释力。研究应关心决策之间如何相互约束、更新如何传播、什么观测改变什么动作。

“四段集成”也不单独足够。它可以带来实用系统或评估平台；要成为主方法贡献，需证明这种组织产生了一个可复现、可解释的性质，例如任务完成后能准确撤销相应获取方向，同时保留相关事实与偏好，并在已有内容充足时避免错误换题。这个性质也必须接受完整近邻和简单组合的挑战。

**“更宽的任务”与“更好的方法”是两种不同主张。** 开放获取、连续真人反馈让问题更贴近使用情境；这使研究值得做，但不能直接证明一个新控制器优于已有控制器。正面结果也不要求每个组件都新，只要求最关键的设计关系和发现有实质价值，并排除更简单解释。

## 5. 最推荐的架构增强：把任务进展变成可执行依赖

### 5.1 只优先补这一项

**[提案] 给状态修订和行动选择之间增加明确的依赖模型。** 它统一处理“用户正在完成什么、哪些需要已满足、哪些事实只是观察或推断、当前内容能支持哪一步”，再决定哪些旧计划应失效、哪里需要新获取、哪里只需重排。

这保留了整个搜推问题。消歧只是在证据不足时的一种局部情形；不强迫每轮做探索，不要求新的训练器，也不让成本函数主导故事。该提案是值得试的候选机制，**本报告没有证明它首次出现或一定有效**。ClawRec 的任务状态及功能性规划是它必须超过的起点。

### 5.2 最小但完整的方法规格

| 规格项 | 建议明确到什么程度 | 相对当前 v0.3 新增的可检验内容 |
|---|---|---|
| **任务进展状态** | 当前任务、尚需支持的方面、用户明确完成/掌握的事项、临时约束、可持续事实；均附原事件引用和未知状态。任务结束不删除无关兴趣。 | 不只总结“喜欢什么”，而是表达“接下来还需要什么”；不能由一次点击推断学会或完成。 |
| **修订影响范围** | 每次修改指出它修正哪个任务/约束，影响哪些获取方向和候选判断。已有查询、候选及展示记录引用相应任务与状态版本。 | 旧任务结束或要求修正后，相关计划和候选资格需重新判断；无关任务和偏好保持。 |
| **内容支持关系** | 现有候选分别支持哪些未完成需要，是否满足可核实约束，哪些属性未知。使用各方法共用的内容解释/评分组件。 | 区分“很多同类相关条目”和“能支持当前下一步的内容”；不能只以候选条数代表任务覆盖。 |
| **行动选择规则** | 已有内容足以支持当前需要时重排；确有未覆盖的需要时按该需要获取；证据不足以修订状态时保持；检索失败进入执行状态。多个可行行动允许并列。 | 输出每项行动针对的具体缺口及所依赖状态；下一轮按真实返回重新评估，而非继续执行已失效计划。 |
| **接受和结果回读** | 执行器检查可写范围、动作前提、真实候选和权限；过时结果按当前任务重判。只有用户新证据能确认用户状态，工具完成只确认执行状态。 | 能区分“搜到了”“看到了”“用户掌握了”，避免把系统动作和自己的判断回灌为用户事实。 |

**[提案] 控制循环的实质应能写成以下关系，而不是只给一张 JSON：**

```text
读取本轮可见事件、已有任务状态、候选与工具状态
提出有事件依据的任务/事实/偏好修订，检查后提交
计算修订影响的需求、获取计划及候选判断
在接受的任务状态下，更新现有内容对当前需要的支持情况
从满足前提的获取、重排、保持中选择，明确针对的需要和等待的真实观测
执行；用户新行为或工具新结果到来时回到上述过程
```

其中“影响范围”和“内容支持”必须进一步给出提示、字段、规则和失败分支；不能把这两行隐藏成万能黑箱。“支持评分”只是模型判断，不可宣称它是真实满意度、可靠概率或因果归因。适合做硬检查的 ID、状态版本和动作权限交给程序；语义理解交给冻结模型。

### 5.3 预期行为与可推翻预测

相机已购买后，“选购”结束，“拍摄孩子运动”开始。已有评测不会全被永久判为无用，其中真正讲跟焦的部分仍可能适用。用户说基础已会，只撤销基础教学需要；不推出永远不需要基础，也不删除摄影兴趣。若候选已有合适跟焦教程，先调整展示；没有则获取。一次源超时只改变源执行记录，不修改用户兴趣。

应验证三项预测：**需求变化后更快得到有用内容、无关状态更少被误改、稳定任务中不因过度干预损害体验。** 后两项不是附属美化：如果多搜能提高有用内容，却持续污染其他偏好，就没有证成可靠的连续控制。

把同样的任务字段、支持摘要和解释器提供给强通用 Agent 后，如果它同样做到这些，收益属于表示/组件，不能归给专门选择机制。若 ClawRec 适配后同样做到，也不能把任务生命周期重新命名成 Waterfall 创新。

## 6. 最值得吸收的五项，以及如何证明超越组合

| 优先项 | 分类与具体落点 | 解决的问题 | 创新归属与必要比较 |
|---|---|---|---|
| **ClawRec 的证据关联状态和来源功能规划** | **直接采用基础能力。** 放在事件—状态层和获取工具输入；保留原始行为/解释分离、任务时效、来源承担的功能。 | 来源不同却只按同主题堆叠，短时行为被误当永久偏好。 | 明确引用并给所有完整基线。Waterfall 的独立主张只能是上述状态如何参与跨阶段修订，不能重报这些组件为原创。 |
| **RecBot 的结构化指令与局部冲突更新** | **适配机制。** 放在统一解释器中；正负/软硬区分再附任务范围、作用对象和证据。 | “这些太基础”被误写成全面负偏好，明确限制被普通相似度淹没。 | 先做共同 Parser；Waterfall 与强基线使用同一输出。再单独替换 Parser，报告语言组件的增益，不混入控制增益。 |
| **InteRecAgent 的候选共享、执行记录与反思入口** | **直接采用基础能力，再适配回读。** 放在候选库和执行层；返回候选摘要、错误和动作记录；允许重新规划。 | 控制器不知道现有内容与执行失败，只能盲目继续搜索。 | 完整组合基线同样拥有这些能力；不能用“我们看工具结果、它不能”作比较。Waterfall 额外研究任务变化如何约束修复。 |
| **MARS 的局部记忆操作与按需维护** | **适配机制。** 放在允许写入的状态工具中，优先采用局部修改与跳过；是否增加画像综合层由需要决定。 | 整体画像重写破坏旧知识，每次行为都触发不必要更新。 | 不必照搬全部层级和数值强度。用同状态接口的 MARS-style updater 做替换，区分记忆质量与行动选择收益。 |
| **ToolRec / ChainRec 的动态路由思想** | **优先作强基线。** ToolRec-style 在现有候选和返回上检查差距再选工具；同动作通用 Agent 允许逐步重选、停止。 | 防止将“动态”本身当新方法，揭示更简单的工具循环是否已足够。 | 采用其能力不等于复现原系统；ChainRec 的训练路线可作相关工作/独立对照，冻结版本应标为 inspired/style，不能冒称原作者结果。 |

**[提案] 不推荐当前引入：**为了新颖性训练完整策略、叠加多个同质 Agent、加入 SAGER 全套用户 policy 演化、或引入 MemRec 跨用户协同图。这些不是坏方向，但会增加独立研究问题，24–40 人短会话也不足以自然支撑大规模协同主张。先把统一搜推机制定义清楚。消歧获取保留局部选项，不作全系统必须依赖的中心。

### 完整强基线应怎样搭

把共同成熟底座记为 **B**：同一冻结模型、可见原始经历、解释器、状态读写工具、候选摘要、来源适配器、评分器、重试权限、曝光测量与稳定展示规则。B 也能访问证据和修订状态。它不是只会依序盲目执行的弱流水线。

| 条件 | 保留什么 | 只改变什么；回答什么问题 |
|---|---|---|
| **B＋合理共享状态流程** | 全部成熟底座，触发节奏在开发集调好，允许基本供给检查和错误恢复 | 决策依赖是预设流程；检验复杂控制是否胜过完整的便宜组合。 |
| **B＋通用动态 Agent** | 同状态、工具、观察和权限；允许按返回重规划 | 用通用规划提示替代专门机制；检验是不是现成 Agent 已能完成。 |
| **ClawRec-adapted** | 原有证据状态、来源角色、反馈、有限补搜与新事件重新规划 | 只作必要接口适配并逐项披露；检验是否超过最近整体方法。再允许它使用共同供给/结果检查，避免故意漏补显然能力。 |
| **B＋Waterfall 提议机制** | 同一底座 | 加入明确的任务修订—受影响需要—内容支持—行动依赖；这才是方法主比较。 |
| **机制替换诊断** | 保留所有组件与原始信息，阶段依然能正常执行 | 将显式依赖传播替换为通用重规划；将按需要的支持判断替换为普通候选数量门控。检验复杂部分到底有没有贡献。 |

还要拆开两种比较：**表示价值**可比较普通历史摘要与任务进展表示，但必须承认输入加工发生了变化；**控制价值**则给对手同样的任务进展表示及候选摘要，只替换行动选择。否则会把更好的状态写法误报为控制器更优。

评分器、来源角色、重试能力或可见历史的改善，应当单独报告或统一提供。近邻原生实验可以另表复现；没有原权重、代码或训练条件时，只能写 style/adapted。不能直接拿各篇原论文分数横比，更不能要求 RecBot 或 MARS 的原模块独立完成其未定义的开放搜推任务。

## 7. 数据与证据：24–40 人怎样真正帮助主线

**[判断]** 这一规模名义上提供约 18–40 人时，适合观察有限时长的任务进展、纠正和系统恢复。统计效力取决于实际差异、任务方差、组内相关和流失，需要先导校准；不能把几千次点击当作几千名独立参与者。若还从总人数中划走开发组，应按剩余测试人数重新判断能支持的主张。

**[提案]** 真人主比较聚焦完整 Waterfall 与开发协议选出的强基线；其他方法在受控环境和外部任务诊断。参与者顺序平衡，任务集合匹配但不直接重复同一道已学会任务，减轻学习与疲劳迁移。保留真实个人需求任务，同时把预设目标切换压力测试单列，避免把照着脚本说纠正语句写成自然行为。

数据至少需要区分：用户原话/操作、真正进入可视范围的内容、内容当时版本、系统做过的工具调用与错误、每次状态修订、后续真实反应。任务进展由参与者事后核对或其他独立证据确认；研究者推断和模型生成另列。用户私有目标标签不能偷偷返回控制器。

主结果可沿用“在可比时间或曝光机会内遇到的有用独特内容”，具体 U@40 是否合适由先导确定。任务完成后停下可能是好结果，不能仅因少看内容判低分；任务进展与完成度应作解释性结果。点击/停留是输入，不能又直接定义满意；短列表、无结果、失败和中途退出不能消失。

对不同策略，要让参与者反馈对应各自实际展示。已记录的同一条点击轨迹不能强塞给所有策略。模拟实验可以提供规模和诊断，必须与真人结果分开；评价器与反馈器不向控制器泄露答案，且要用人工检查其一致性和偏差。置信区间以用户或整条轨迹为单位，而不是把相关点击拆散。

资源发布要证明外部研究者能用它做什么：状态理解评估、动作选择诊断、明确边界的轨迹回放和标准化新交互协议。只有静态截图和零散正例，不足以支撑“真实连续交互基准”。真实/合成标记、去标识化、同意与撤回方式、内容再分发许可和版本均需清楚记录。

## 8. 推荐路线和研究检查点

以下是后续研究顺序，不代表本次已执行或授权立即招募/实验。

| 阶段 | 应交付的具体东西 | 继续推进的条件；应当停止扩张的信号 |
|---|---|---|
| **1. 冻结方法差异** | 一页可执行机制、状态/动作契约、失败分支；逐项对应 ClawRec、ToolRec、InteRecAgent、ChainRec 的能力 | 删除 Waterfall 名称后仍能说明哪条决策关系不同。若只剩换字段或统一提示，不应先大规模实现和采集。 |
| **2. 构建共同底座和完整对照** | 同一环境中的共享状态流程、动态 Agent、ClawRec 适配与候选机制；完整决策日志 | 强基线能真正连续运行和修复。若所有差异只是评分/获取权限，应先修正比较。 |
| **3. 小规模先导与反例检查** | 区分任务改变、细化纠正、完成/掌握、无变化、工具失败的轨迹；检查标注与有用性定义 | 候选机制在预先说明的难点上表现出可解释差别，且稳定场景不被过度修改。先导结果不写成最终测试。 |
| **4. 冻结真人协议再采集** | 开发/测试划分、强基线选择规则、顺序安排、可复用记录、参与者判断标准 | 24–40 人确能覆盖主问题；若观察不到真实任务变化，就收缩为短时指令适应，不能补造长期故事。 |
| **5. 主比较与归因** | 真人主结果、受控机制替换、近邻对照、负面案例和不确定性 | 主效果、机制证据和适用边界相互一致；否则按下表撤回相应主张。 |
| **6. 据结果重写论文** | 以实际方法和发现同步 Introduction、Method、Data、Results、Limitations；再次核对 ACL 政策 | 方法和资源分别陈述其贡献。没有结果前不预填提升；结果弱时也不自动改成资源论文并宣告可投主会。 |

### 强基线追平时，哪些主张必须撤回

| 观察到的结果 | 必须撤回/收缩 | 仍可诚实保留 |
|---|---|---|
| B＋通用 Agent 与 Waterfall 相当 | “专门统一控制机制优于通用规划”“必须用一个专门控制器” | 任务定义、可用实现、数据和一般 Agent 在此场景的能力/局限发现。 |
| 共享状态流程或普通门控追平 | “细化跨阶段控制是收益关键” | 共享状态/简单规则的作用；需要重新判断是否有足够重要的发现。 |
| 只有换更强解释器/评分器才提升 | “统一控制带来增益” | 语言解释或排序组件的增益，按真实来源归属。 |
| 只有模型模拟中胜出，真人没有可信支持 | “改善真实用户体验或任务完成” | 特定模拟协议下的结果与模拟—真人差距。无显著差异也不自动等于等效，需看区间。 |
| 只在直接、明确的语言命令后改善 | “能从日常隐式行为持续理解任务进展” | 明确语言纠正下的控制能力。 |
| 数据主要是短期脚本互动 | “自然长期适应”“普遍跨任务个性化” | 有边界的受控短会话数据与发现。 |
