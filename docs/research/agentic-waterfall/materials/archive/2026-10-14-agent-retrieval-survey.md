# Waterfall：Agent 召回的近邻工作与问题定义

> 历史材料：保留当时内容，不作为现行方案。当前以 [研究主方案](../../01-研究主方案.md) 和 [输入输出与数据流](../../02-输入输出与数据流.md) 为准。

核验日期：2026-10-14。范围：优先阅读论文原文、正式会议页、作者官方仓库；下表是与 Waterfall 接近程度最高的选择性调研，不是穷尽性综述。没有运行这些系统，也没有复现论文数值。

## 核心判断

**“Agent 看用户行为、维护长短期偏好、跨来源查内容、再排推荐列表”已经有很近的工作，不能据此宣称新颖。** 最需要正面对比的是 ClawRec、AgentWebBench 和 Meta 的 CTV 内容发现系统。把模块叫 M/S、让模型输出 JSON 操作、设置内容池阈值，也不能单独构成研究贡献。

需要先区分两种工作：

- **当前实现边界（由主调查者本轮 PPT/代码核验提供）**：S Agent 输出兴趣强化/削弱、S 保留/替换/清空，S 最多 5 个主题；程序按启用来源与 P/S/E 配额执行检索，内容池低于 80 补充。它首先是“行为驱动的记忆与检索计划修订”。
- **尚未核实为已实现的研究设想**：Agent 看本轮搜索结果后，自主决定换来源、改查询、翻页或停止。这才是更完整的交互式召回策略，不能将设想写成已有实验成果。

## 十组最相关工作

| 工作、状态 | 输入 → 动作/输出；怎么验证 | 与 Waterfall 的重合、边界 |
|---|---|---|
| **ClawRec**，2026 预印本；有官方代码 | 跨平台行为、历史、聊天和反馈 → 统一事件、用户状态、来源规划、检索、跨源推荐列表。区分当前任务、持久偏好、过期信号；预算内支持查询恢复，反馈关联回规划。[论文 §2](https://arxiv.org/html/2607.23779v1)、[官方库](https://github.com/wuchenghao0215/ClawRec) | **最强近邻**。不能把结构化事件、时效状态、跨源规划、反馈闭环当成独创。其 SimBench 用模拟意图驱动 GUI 产生轨迹；评估下一步任务支持度，主要用模型评分，不等于真实用户长期满意度。[论文 §3–4](https://arxiv.org/html/2607.23779v1) |
| **CTV Content Discovery**，Meta，2026-07 预印本 | 长期兴趣、session 活动、停留/跳过、事件上下文 → LLM 产主题 → 专门模型召回和排媒体 → LLM 排主题；异步补缓存。评估媒体主题相关性和服务性能。[论文 §3–4](https://arxiv.org/html/2607.09988v1) | **直接覆盖“慢 Agent + 快排序 + 缓存”**。它主要在平台内部做内容发现；§5.1 明确将跨阶段质量反馈、跨 session 学习列为后续方向。未核实公开数据/完整可复现代码，不能当现成公共基准。 |
| **AgentWebBench**，**ICML 2026 正式论文** | Web Recommendation：浏览历史 → 推断意图、选网站、调用内容 Agent → 排序网页。100 站、1840 万文档；推荐子集 281 条；与集中检索、向量选站、LLM 选站比较。[PMLR](https://proceedings.mlr.press/v306/zhong26n.html)、[正文 §3](https://arxiv.org/html/2604.10938v1) | **“Agent 做个性化跨站召回”已有专门基准**。其推荐任务多数组合命中接近 0；下一网页常与历史弱相关，标签稀疏。适合压力测试，不能独自证明 feed 体验。[附录 H](https://arxiv.org/html/2604.10938v1) |
| **PersonalWAB / PUMA**，**WWW 2025 正式论文** | 指令 + 画像 + Amazon 行为历史 → 选函数及参数。函数包括 `search_product_by_query`、`get_recommendations_by_history`、`respond`、`stop`；底层搜索用 BM25，推荐用 SASRec。评估选函数正确、返回结果正确、步骤数。[正文 §4–5](https://arxiv.org/html/2410.17236v2)、[官方库/会议信息](https://github.com/HongruCai/PersonalWAB) | **“最后输出操作”早已存在**。Agent 可调用传统召回/推荐模型，未必自己给每件内容算分。它以商品任务和用户请求为主，不是持续跨平台内容流。 |
| **Orion**，**AAAI 2026 正式论文** | 历史 + 当前请求 → 全局/细粒度画像、动态上下文更新、Web API 或澄清动作；用 PersonalWAB 的扩展商品任务，测结果与步骤数。[会议页](https://ojs.aaai.org/index.php/AAAI/article/view/40188)、[正文 §3–5](https://ojs.aaai.org/index.php/AAAI/article/view/40188/44149) | **长期稳定偏好 + 当前场景 + 意图变化，不是空白**。基于商品记录和模拟多轮交互；不直接覆盖真实跨平台 feed 的停留反馈与连续补池。 |
| **ReSLLM / TREC FedWeb**，ReSLLM 2024 预印本、2025 WWW Companion 论文 | 查询 + 来源描述/历史摘要 → 为来源打分、决定问哪些搜索引擎。用 TREC FedWeb 2013/14 判断选源质量。[原文](https://arxiv.org/html/2401.17645v1)、[作者论文目录中的发表记录](https://wshuai190.github.io/files/thesis.pdf)、[NIST FedWeb](https://trec.nist.gov/pubs/trec22/papers/FEDERATED.OVERVIEW.pdf) | **选来源、合并多搜索引擎结果是成熟问题；LLM 选源也已有**。不包含长期个人行为驱动的持续发现。Companion 不应写成 WWW 主会 full paper。 |
| **Rewrite–Retrieve–Read / Search-R1**，**EMNLP 2023 / COLM 2025** | 前者把输入改成更好的查询；后者在推理中多次搜索、读取结果再继续，最终回答问题。[EMNLP 原文](https://aclanthology.org/2023.emnlp-main.322/)、[Search-R1 会议稿](https://openreview.net/attachment?id=Rwhi91ideu&name=pdf)、[官方库](https://github.com/PeterGriffinJin/Search-R1) | **改写查询、多轮搜索、输出工具动作本身不新**。它们主要测问答，不测推荐喜好；问答准确率不能替代 Waterfall 的推荐评价。 |
| **Spotify：You Say Search, I Say Recs**，**RecSys 2025** | 探索性请求，如“适合我的新歌” → LLM router、搜索/推荐 API、子 Agent → 个性化结果。[Spotify 官方论文页](https://research.atspotify.com/publications/you-say-search--i-say-recs-a-scalable-agentic-approach-to-query-understanding-and-exploratory-search-at-spotify) | **Agent 调度搜索与推荐已有工业工作**。平台内、用户发起查询；其私有实验不能直接复现为 Waterfall 基准。 |
| **ORBIT / ClueWeb-Reco**，**NeurIPS 2025 Datasets and Benchmarks** | 浏览历史 → 推荐下一网页；授权真实历史映射到公开网页形成隐私保护数据，隐藏测试用于排行榜。[正式论文](https://papers.nips.cc/paper_files/paper/2025/hash/e1a6951efe00913c584b48e668bc2215-Abstract-Datasets_and_Benchmarks_Track.html)、[官网](https://www.open-reco-bench.ai/) | 比商品数据更贴近网页发现；**隐藏测试不是可随意下载改造的训练集**。下一次访问只是一个行为记录，不是用户所有愿意读的内容集合。 |
| **PersonaTrail / PACMem**，2026 预印本 | 时间、URL、元素、点击/输入轨迹 + 含糊请求 → 事实记忆/偏好记忆 → 导航到页面；测试偏好推断和过去事件找回。[原文 §3–4](https://arxiv.org/html/2607.20482v1) | **结构化浏览轨迹 + 分层记忆 + 动作已有**。虽在真实网站执行，轨迹由 Agent 根据 persona 合成，时间间隔也模拟；不要称为自然人真实停留数据。 |

## 最近增量：还需进入全文 related work 的竞争者

- **MediateRec / PAMO，2026-10-06 预印本**：个人 Agent 用跨平台历史修改平台原始排名，专门统计“救回原本漏掉的好内容”与“错删原本排对的好内容”。这否定“用户侧跨平台 Agent 重排”这个宽泛首创说法。论文脚注写基准需内部批准后发布，本轮未核实已公开，不能承诺直接下载使用。[论文 §3–4 与脚注 1](https://arxiv.org/html/2610.07588v1)
- **Tasteprint，RecSys 2026 Demo 官网条目**：问卷 + 13 个服务的授权活动，生成可携带的跨域画像，再供宿主 Agent 搜索/推荐；有本地文件和用户修订。它是 Demo 证据，未核实其效果实验，不能等同成熟算法基准。[会议官方页](https://recsys.acm.org/recsys26/demo-presentations/)
- **PersonaMem-v3，2026 预印本、10 月 7 日修订**：已把跨平台理解、可控推荐、主动行为列入评估范围。这里仅核实官方摘要和版本信息；输入字段与测评细节由本次另一条数据/排序调查继续核验，不在此下强结论。[arXiv 页面](https://arxiv.org/abs/2608.21381)

## 当前最值得先做的窄问题

**候选问题，不是已证明的创新：在点赞、短暂停留、连续跳过和明确改口混在一起时，Agent 应该什么时候只改当前检索计划，什么时候更新长期兴趣，才能更快跟上现在的需求、又少误改长期偏好？**

例子：这个人长期看摄影；今天连续看了三条东京旅行攻略；其中一条停留长，只是离开了手机；之后明确说“机票已经买了，先别给旅行攻略”。好的系统应停止旅行召回，保留摄影兴趣，且不会把一次长停留永久记成“爱旅游”。

这个问题贴近当前 `reinforce/weaken` 和 `keep/replace/clear` 的可控操作。不能只展示操作 JSON 合法、主题写得合理；需要证明操作**让后面的内容更好**。ClawRec、Orion 都已涉及状态时效和变化，所以真正需要补的是更具体的方法、可复现实验及对近邻的实证增益。

最小对比可以只改变“如何更新 M/S”，固定同一个来源集合、检索器、排序器和预算：

| 对照 | 例子 | 它回答什么 |
|---|---|---|
| 不更新 | 一直按原有摄影兴趣搜 | 新行为有没有帮助 |
| 简单规则 | 最近点赞的主题加入 S，连续跳过后删除 | 模型是否真比便宜规则好 |
| 每轮整体重写画像 | 所有历史交给同一个 LLM 重写 | 显式增量操作是否减少误改 |
| M/S 分离、固定更新规则 | 长期偏好缓慢更新、短期计划快速替换 | 收益来自长短分离，还是来自 Agent 决策 |
| Waterfall 增量操作 | 有证据时强化/削弱，S 保留/替换/清空 | 当前真正要验证的方法 |
| ClawRec / Orion 的对应适配 | 保留其状态更新思想，在相同输入接口上比较 | 是否只重复已发表方法；适配处必须写明 |

记录三件容易理解的结果：用户改口后还要看几条错误内容；应保留的长期兴趣被错删多少次；同样费用和等待时间下，前 10 条里有多少用户认可的内容。内容偏好要来自隐藏行为或独立人工评价，不能让系统先看到答案、再生成“漂亮解释”。

## 如果以后扩成真正的召回 Agent，怎样测

召回是“先找一批候选”，排序是“候选里谁放前面”。先隔开测，才知道改进来自哪里。

**固定环境例子（说明方法，不是实验数据）**：三个来源共 1,000 篇可访问文章；对某个需求，独立标注出 20 篇有用文章。每个系统最多发 5 次查询、最后带回 100 篇。A 找到其中 12 篇，B 找到 16 篇，召回率分别为 12/20=60% 和 16/20=80%。同样的排序器再从各自 100 篇挑前 10，才能比较整条链路。

应有的对照是：固定查询/固定来源，历史生成一次查询，LLM 一次选源，再到允许读取结果后调整的 Agent。采用相同底层搜索接口、结果页大小、去重规则和预算；额外记录调用数、费用、延迟、重复内容。否则“多搜了十倍所以找得更多”不能证明策略更好。

数据可分两层：先用有固定语料和相关性标签的检索集验证“找得到”；再用真实行为/人工偏好验证“这个人愿意看”。把同一数据集切成三个虚拟来源可测试受限接口，但只能称模拟多源环境，不能当真实跨平台用户证据。AgentWebBench 可作已有跨站环境；不要把 QA 基准的答对率包装成推荐效果。

**真实 Web 无法知道全网到底有多少好文章时，就不能诚实地报“全网召回率”。** 可以汇总各方法找到的文章，打乱后让独立标注者判断，以这个已评集合报告结果，并明确不完整；同时保留搜索快照/回放，降低网站随时间变化造成的不公平。

## 调研结论的使用边界

可写：“Waterfall 研究基于行为证据的可控兴趣与检索计划更新，考察其在意图变化下的准确性、稳定性和实际内容收益。”

暂时不能写：“首次用 Agent 做召回/推荐/跨平台画像/操作输出/长短期记忆/反馈闭环”；也不能写“已证明优于传统推荐”。

本轮跳过模型训练、基准复现和线上用户实验。最大风险是把已有系统能力的组合、模拟行为分数或工具调用成功率误当作方法创新与真实推荐收益。
