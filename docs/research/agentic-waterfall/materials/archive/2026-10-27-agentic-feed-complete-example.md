# 用一个完整例子说明 Waterfall 数据怎样产生

> 历史材料：保留当时内容，不作为现行方案。当前以 [研究主方案](../../01-研究主方案.md) 和 [输入输出与数据流](../../02-输入输出与数据流.md) 为准。

> 当前核心入口：[agentic-waterfall/README.md](../../01-研究主方案.md)。逐步数据与并行调用见新例子；主评测以“下一条盲选＋连续使用后续用选择”为准。本页保留作早期规格/研究依据。

2026-10-27。**必需的信息类别现在已经齐全：Agent 可见输入、动作输出、真实执行与曝光、会话结果、研究评价。** 前三类驱动运行，最后两类用于检验效果。这里的“完整”指覆盖本任务从开始到结束的记录，不要求每个人都有历史或每次都有所有反馈。

[完整 JSON 数据](agentic-feed-v1/complete-example.json)记录一个 episode、8 次决策、13 个动作、10 条内容、6 次真实曝光事件。[回放脚本](agentic-feed-v1/replay_complete_example.py)能解析并重放它。**整个样例由作者编写，人物、内容、时间和评分均为示意；它不计入实验。**

## 1. 用户经历与记录，一起看

| 阶段 | 用户看到/做了什么 | Agent 怎样继续 | 具体记录什么 |
|---|---|---|---|
| **新用户进入** | 没填画像、没历史，先随便刷；页面提供摄影、早餐、阅读内容 | d1 获取热榜；收到真实结果后 d2 推荐 | 空初始状态、来源能力、获取参数/返回、排队列表；摄影与早餐实际曝光，未看见的阅读内容只记入队 |
| **没有发指令** | 打开摄影文章，读 22 秒并收藏 | d3 记下本次行为，搜索手机摄影；d4 调整后续内容 | 原始打开/停留/收藏事件、关联曝光 ID；“本次关注摄影”的经历记录，以及新查询与候选 |
| **主动提出需求** | “周末用手机拍孩子踢球，不买器材，先给我短教程。” | d5 建立任务、记录不买器材的要求，去视频来源获取；d6 展示视频教程 | 原话及指向对象、状态补丁、实际查询、视频内容与时长、推荐顺序、真正播放的片段 |
| **交互式调整** | “基础设置我会了，只看图文，给我跟拍的具体步骤。” | d7 更新当前要求，从已有候选中选两篇图文；这次不用再搜 | 输入快照、状态版本 2→3、替换未展示队列、两篇图文的曝光、阅读与收藏 |
| **结束与评价** | “这两条够了，我去试试。”随后离开；示例结束评分为 4/5 | d8 结束当前信息任务，停止继续补充；客户端另记会话结束 | 任务完成状态、用户退出原因、最终状态与观察窗口；事后评分单独存，实际拍摄效果未知 |

这覆盖了无历史、无指令、主动要求、跨来源/形态、状态更新、复用候选和退出。获取与推荐不是固定每次都一起执行。

## 2. 一条完整数据长什么样

这里“一条数据”是一段连续使用，而非一行“用户点了某内容”。完整 JSON 分为五组：

| 部分 | 文件中的真实字段 | 含义 |
|---|---|---|
| 运行起点 | `metadata, run_meta, initial_snapshot` | 匿名 ID、开始时间、模型与提示词/动作协议快照、记录规则、初始记忆；样例明确 model.invoked=false |
| 内容环境 | `environment_snapshot` | 当时可查询的内容库、来源、查询规则和内容 hash；例子提供可重放的两来源小型内容环境 |
| 每次决策 | `decisions[]` | 当时完整 input、raw_output、parsed_output、validation、execution_results、state_after；保存输入与输出 hash |
| 实际使用 | `event_log, dialogue_log, slates, feedback_windows, final_snapshot` | 真实曝光与反馈、哪些只排队未看见、观察窗口、状态和会话结局 |
| 研究评价 | `evaluation_private` | 事后有用性、信息需求是否满足、需求变化后的内容判断；与 Agent 输入分开 |

模型请求按 `system_prompt + action_contract_snapshot + 本次 input` 组装；这些材料都保存了。整个未来轨迹、隐藏评价和完整内容库不直接放进某次 input。其他系统也可以通过同一个查询接口自行取得不同内容。

## 3. 怎么采：用户自然用，前后端各记自己的部分

**真人先自然使用约 10 分钟，可提前结束；兴趣填写可跳过。** 有明确需求就说，没有就随便刷。中间不用每看一条都填问卷。

- **网页记录用户行为：**消息原话、实际可见内容与位置、打开、前台阅读/播放片段、赞踩收藏评论，以及进入/离开。一个事件一个 ID，同时记发生时间与服务端收到时间。
- **服务端记录 Agent：**每次实际发送给模型的上下文、原始回答、解析/校验结果；每个来源实际执行的查询、返回内容或错误；每次记忆变更和入队列表。
- **内容单独保存：**来源、标题、原文片段/字幕/媒体引用、获取时间、版本与 hash。仅保存某个系统搜到的结果，可以审计该系统；要比较新策略，还应提供共同的可查询内容快照。
- **结束后只问两题：**“这次内容有多大帮助？”以及“信息是否够用？”无明确任务时第二题换成“是否愿意继续看？”退出、超时和中断分别记录。

本例的曝光口径是：页面在前台，卡片至少一半可见并持续 1 秒。点击或打开可单独发生；阈值前打开内容时，打开事件仍保留，但不伪造一条满足阈值的 feed 曝光。详情阅读另记其实际显示。曝光窗口关闭后，才汇总这个窗口有没有点击；未看见或记录中断保留未知。

结束调查之外的盲选另作一组标注：给出相同的用户上下文，把不同系统生成的列表隐藏名称、随机左右展示，允许平局和都不想看。回顾式盲选用于评价当时内容；连续体验仍通过各系统自己的实际使用过程比较。

## 4. 输出怎样解析并生效

d7 中的推荐动作原文如下；它依赖同批的 a9 状态更新：

```json
{
  "action_id": "a10",
  "kind": "recommend",
  "arguments": {
    "ordered_item_ids": ["p4", "p5"],
    "delivery": "replace_pending"
  },
  "evidence_refs": ["m2", "a4"],
  "depends_on": ["a9"]
}
```

执行过程只有四步：

1. **解析 JSON 并校验：**动作类型、参数、内容 ID、来源能力、状态版本、前置动作。保留原始回答；错误返回给 Agent，不把文本当代码执行。
2. **按依赖执行：**a9 先把本任务改成“只看图文、要具体步骤”；成功后 a10 才生效。相同 action_id 不重复执行；工具失败有独立回执，已成功动作仍保留。
3. **返回真实结果：**a10 返回 `slate_id=sl4, queued_item_ids=[p4,p5]`；前端据 ID 取内容卡片。此刻记录的是入队成功。
4. **等待实际曝光和反应：**p4 真正进入屏幕后产生 x5，随后打开/收藏都关联 x5。它们进入下一次 input，形成完整循环。

新获取内容须等工具返回 ID 后才能推荐。需要解释或提问时用 respond；没有合适动作时用 idle。同一请求可能有多种合理动作组合。

## 5. 怎样评估这段使用

| 要回答的问题 | 本例怎样看 | 正式数据怎样算 |
|---|---|---|
| **内容有没有帮助？** | 用户结束评分 4/5，表示信息够用了；这些是人工设定的示例值 | 真人结束评分、信息需求满足率；随便刷用值得看/愿意继续看，报告实际用户分布 |
| **变化后跟没跟上？** | “只看图文”后，4 秒出现符合要求的 p4；p4/p5 是否有具体步骤由内容判断确认 | 从原话到第一条被评价为符合要求的实际曝光，统计耗时与后续不符合要求的内容 |
| **理解是否更新合理？** | 当前任务只看图文；保留此前摄影经历；“方法够用了”没有被写成“已经拍摄成功” | 根据用户原话/自报事实核对状态，检查要求的范围、过期任务与后续内容 |
| **系统是否真实做到了？** | 8 次决策、13 个动作、3 次来源调用，最终只有 6 次实际曝光 | 解析/执行成功率、等待、重复与未交付；作为诊断，不用点击数代替满意度 |

**不把人工动作顺序当唯一答案。** 另一个系统用不同搜索词、先给图文，甚至少执行几步，也可能提供更好体验。样例的预期断言只验证样例自洽。

正式比较共享初始信息、模型/工具条件和可查询内容环境；真人随机分配系统，各系统接收自己展示后产生的反馈。单步盲选评价内容，整段连续使用评价体验；统计比较以用户/会话为单位，避免把同一人的每次点击当独立样本。若扩大到模拟用户，先在留出的真人选择与系统排序上核验，再用于覆盖更多场景。

## 6. 新参考带来的补充

[RecSim](https://research.google/blog/recsim-a-configurable-simulation-platform-for-recommender-systems/)支持区分用户内部状态和 Agent 可观察信息；[τ²-bench](https://github.com/sierra-research/tau2-bench/blob/main/docs/evaluation.md)提供按结果评价、允许不同工具轨迹的参考；[Open Bandit Dataset](https://github.com/st-tech/zr-obp/blob/master/obd/README.md)提示保存实际展示位置与已知随机选择概率。这些补充与已有 KuaiRand、MIND、RecBot、ClawRec 的字段参考共同形成当前协议。概率没有被真实记录时填 null，不用模型置信度代替。

运行 `python3 docs/research/agentic-waterfall/materials/archive/agentic-feed-v1/replay_complete_example.py` 可检查输入时序、内容查询、状态变更、推荐、曝光、反馈和评价引用。脚本还检查坏 JSON、未取得内容 ID、过期状态三种错误。该脚本只回放作者样例；真实来源连接、真人采集和模型调用留给 demo/采集实现。
