## 一页摘要

**研究对象：用户边看边表达，Agent 同时利用当前指令、实际行为、完整的已授权 profile/memory，连续决定获取什么、展示什么、记住什么，以及何时保持或结束。** 用户不必每轮说话；工具返回与实际曝光后的行为也能触发下一次决策。候选内容由系统自己的获取动作产生，后续证据又取决于实际展示，所以任务同时涉及语言理解、内容获取、推荐编排和状态维护。

这不是尚无人提出的四模块拼图。[RecBot](https://arxiv.org/html/2509.21317v2)已有信息流内语言控制和动态工具链；[ClawRec](https://arxiv.org/html/2607.23779v1)已有证据状态、跨源规划与推荐；[MARS](https://arxiv.org/html/2605.14401v2)已有分层记忆及维护动作。**统一定义本身不等于新算法。** 建议论文的两条共同主线是：一套可执行的持续搜推任务与参考框架；一套能测量该任务的真实交互资源、可复现实验环境和诊断协议。其学术分量由强基线下的新发现与实际效果建立。

最小接口保留三类用户输入，外加候选、工具、预算和执行状态这些环境信息。输出是多选动作集合：`update_state`、`acquire`、`recommend`；补充 `respond` 与 `idle`，分别承载必要沟通及保持/等待/结束。真实检索返回前不生成不存在的候选 ID。运行时状态变化不等于模型训练。

必须检验三件事：**语言与行为的联合解释是否改变了正确动作；获取、展示与记忆之间的协调是否有超出成熟组合的价值；单步排序分数是否遗漏持续交互中的重要失败。** 历史纠错、含糊反馈、目标切换、无指令浏览、来源/模态切换和任务完成都进入同一任务分布，任何一个都不独占主线。

ACL 落点是自然语言如何在真实浏览语境中指向对象、限定范围、解释行为并约束后续行动。主表要包含语言条件下的决策质量与连续有用性；不能只报告点击率，再以使用 LLM 说明语言贡献。**下一步先冻结本稿的公共接口和场景矩阵，再将所有强对照接到同一环境；本稿不启动实验。**

## 2. 完整任务定义：持续搜推，而不是某一种修订

**[提案]** 一个 episode 是用户实际浏览内容的连续过程，既包括围绕一个或多个可变化目标的浏览，也包括没有明确目标的日常探索（open-ended exploration）。后一种情况不要求用户先提出任务，也不替用户编造隐藏目标；这里的完整任务定义同时覆盖这两种使用方式。系统在决策点收到：

- **Command**：当前明确要求、评价、说明、纠正或普通对话；可以为空，保留原话与指向内容。
- **Behavior history**：截至此刻真实发生的曝光、点击、赞踩、收藏、评论、停留、滚动、回访等。必须保留事件时间和对象；评论区中别人的话不等于用户自述。
- **Profile / memory**：所有向本次系统授权开放的用户事实、偏好、当前/已结束任务、已有记忆和证据。这里的“完整”指可访问范围一致，不是把用户没有提供的信息当作真值，也不强制每次把整库塞进提示词。

另有环境状态：已到达候选、已展示内容、正在执行的动作、来源/模态能力、检索结果和失败、剩余预算。它们是任务运行条件，不是第四种用户画像。

可写成 `decision_t = policy(command_t, history_≤t, user_state_t, environment_t)`，输出状态变化与动作集合，执行结果进入下一次 observation。真实偏好和实际效用不是系统可见变量；本定义不宣称发现新的 POMDP，也不要求训练 policy。

### 为什么不能只用一个更好的排序器衡量整个任务

| 同一任务里的情况 | 真正需要的决定 | 仅固定候选排序缺少什么 |
|---|---|---|
| 用户从相机选购转到运动跟焦学习，池里都是商品测评 | 更新任务，获取教程，再推荐 | 没有合适候选，重新排序不能创造所需内容。 |
| 用户说“太长了，给我短一点的”，池里已经有合适短教程 | 仅调整相应约束与顺序 | 每次全量搜索浪费时间，也可能替换掉本来适合的内容。 |
| 看了几篇旅游攻略后说“帮同事查的，我自己不去” | 调整该行为支持的任务/偏好，保留独立有效信息 | 下一屏正确不保证以后不会重新把旧行为解释为本人需求。 |
| 用户没有说话，只在已展示内容中连续关注同一问题 | 保留弱证据或逐步调整，必要时补充内容 | 不应要求每轮都有语言标签，也不能把停留直接等同喜欢。 |
| 搜索返回空结果，或者用户说“已经解决” | 分别决定换来源/保留已有内容，或结束当前获取任务 | 空结果不表示用户不喜欢；继续灌入内容也不等于成功。 |

这些说明评测必须覆盖多种决定，**不是证明端到端强 Agent 无法解决它们**。充分上下文、同工具的强通用 Agent 正是必备对照。将全部环境预先封成静态候选也可以做受控子实验，但不能代替获取与后续反馈的整体任务。

整体成功定义为：在实际可用内容、用户表达的要求和共同预算下，连续提供有用或值得看的内容，同时保存与证据相符的状态。有明确目标时，评价内容是否帮助任务进展、完成及合理停止；无明确目标时，评价内容是否值得看、是否带来新信息、用户是否愿意继续浏览，不要求恢复一个假设存在的隐藏目标。点击或更长使用时间只能是行为信号；单独增长不能定义成功。

## 4. 参考框架：吸收成熟做法，把共同底座做强

**[提案]** 采用一份事件记录、一份公共用户状态、一份真实候选池和一个动作执行器。理解、获取规划和推荐可以是同模型的多个调用，也可以是一个控制器；模块数量不作为贡献。

| 吸收来源 | 进入 Waterfall 的具体部位 | 归因与公平性 |
|---|---|---|
| RecBot 的约束解析与局部更新 | 原话转正/负、硬/软要求；兼容合并、冲突时只改相关记录。 | 沿用其思想；强组合基线也使用。不要把新 JSON 字段当成新解析算法。 |
| ClawRec 的证据状态、来源角色与互补性 | 记录当前任务、可复用偏好、来源用途；针对需要的信息功能获取，选择互补内容。 | 来源不是越多越好；任务需要同一来源时允许集中。共同基线保留相同能力。 |
| MARS 的记忆维护操作 | 对同一状态库执行局部增强、弱化、合并、失效和摘要刷新；无需更新则跳过。 | 不再新增互相冲突的第二套画像；strength 不是已经校准的概率。 |
| 现有推荐/检索工具 | 内容匹配、过滤、去重、真实链接与模态元数据；获取返回候选后才能展示。 | 模型能调用成熟工具，不能把工具能力差异伪装成控制能力差异。 |

控制器要做的具体决定是：本轮哪些用户理解需要变化，变化适用于哪一层；已有内容是否覆盖当前需求；还缺什么信息功能/来源/模态；本轮能执行哪些互不冲突动作；实际结果是否改变下一步。它不必执行“更新→搜索→排序”的每个阶段，也不能因为单次搜索失败就改写用户偏好。

初版采用透明、可检查的参考规则即可：明确有效要求先约束状态和候选；有可用候选时直接推荐；有内容缺口且预算允许才获取；结果到达后检查缺口是否补上；不足时在预算内改来源/查询或说明局限；无新证据保持，无需服务的任务结束。**这些规则是参考实现，不预称新算法。** 如果后续发现一种独立、可复现的决策机制能优于强基线，再把它作为方法贡献单独陈述，不先把整套系统缩成纠错或探索的一个分支。

## 5. 什么能够成为论文贡献

### 5.1 推荐的贡献结构

1. **任务与框架贡献。** 给出完整可执行的 agentic feed 任务，把三类用户输入、开放候选获取、连续曝光与可修订状态放入一个可比较协议，发布可运行参考系统。价值在明确新的研究对象与可复用接口；接口本身不是新算法。
2. **数据与评测贡献，可占约一半。** 建立包含实际曝光后自然语言/行为、可重放内容环境、时间与来源证据、状态和动作判定的资源；把真实观察、研究者控制和模拟数据分开。其价值需要来自难点覆盖、标注可靠性、外部可复用性及此前指标遗漏的问题，不能只靠“我们采了一个数据集”。
3. **实证与解释贡献。** 用同信息、同工具的强组合和通用 Agent 测出哪些语言/行为现象困难、哪些阶段互相依赖、现有分数为什么失真，并验证有效做法。真实负结果也可以形成发现；不能把未显著结果改写为全面优势。

**可行的 field-defining 路线，是让后续研究能够直接复用我们的任务、环境、数据和比较办法。** 五项交付按依赖顺序推进：

| 交付 | 具体完成形态 | 为下一步提供什么 |
|---|---|---|
| 任务 | 完整输入/动作/成功定义，覆盖无话语、目标变化与正常结束。 | 各研究者解决同一个问题，知道什么信息可见。 |
| 协议 | 真实候选与曝光 ID、工具返回、状态版本、成本及时间记录；同前缀可重放。 | 不同实现可以公平接入与检查。 |
| 基准 | 自然交互资源、冻结内容环境、受控分支和语义标注；公开划分及不可判定项。 | 有完整的难点分布，而非只测试几个演示口令。 |
| 参考实现 | 最小公共执行层、成熟组合、同动作通用 Agent 及 Waterfall 控制器。 | 新方法能够复现实验，不需重造产品。 |
| 关键发现 | 解释哪些语言/行为组合改变正确动作，哪些协调机制有效，一步指标漏掉哪些用户后果。 | 给出可累积的知识，以及后续方法明确要解决的问题。 |

数据与协议、基线和分析可以共同占据约一半正文与研发投入。正向目标是交付一个别人愿意接入并能复现新发现的研究对象，而不是先给一个小机制命名，再为它凑场景。

### 5.2 三个可验证命题

| 编号与主张 | 决定性的比较 | 支持需要的证据 / 反证 |
|---|---|---|
| **P1：语言、曝光语境与历史共同决定有范围的意图，能改变获取、推荐和记忆的正确动作。** | 同一句原话配不同曝光、行为或任务；覆盖否定/范围、任务变化、无话语、委托与纠正。比较完整输入、去语境、去语言及强通用 Agent。 | 合理动作与状态产生语义正确的变化，并改善当前及后续内容有用性；仅记住模板或让画像更好看不够。 |
| **P2：按实际状态与内容缺口选择多种动作，能比成熟组件的固定流程更好地服务连续需求。** | 同前缀下设置合适内容在池内、仅库内可检索、不可得三个条件；同预算比较连续 ClawRec、成熟组合、同动作通用 Agent、全日志重读与框架。 | 能正确重排、获取、保持或结束，在多种任务及未见用户/措辞上改善效用和状态；若通用 Agent/成熟组合追平，则明确策略优势未获支持。 |
| **P3：曝光后真实交互与联合动作评测，能够揭示仅用下一条/下一屏排序遗漏的重要失败。** | 同批系统同时测一步排名、闭环效用、语言约束、状态证据、任务进展与成本；人工核验发生分歧的病例。 | 预定义失败被一步指标漏检、对用户有实际影响，并能在未见数据复现。若两类评测一致，则如实报告指标适用边界。 |

P1、P3 可以成立而 P2 的方法优势不成立；这样的结论仍能支持有价值的任务和资源研究。论文应依据证据决定方法与资源的比重，而不是要求所有命题都“成功”。上述是待验证命题，不是预定实验结果。

## 6. 强组合基线与必要控制

| 条件 | 必须保留的能力 | 用途 |
|---|---|---|
| **连续 ClawRec 适配** | 完整事件→状态→跨源规划→获取→互补推荐→反馈；每个决策点可重规划，保留合理扩词、失败处理和来源状态。 | 最接近完整范围的外部比较；公开适配差异。 |
| **成熟组合流水线** | RecBot 式语言约束+ClawRec 式证据状态/跨源获取+MARS 式维护，合理触发反复运行；同一个状态库。 | 检验成熟组件正常组合是否已足够，避免以旧产品原型作唯一对照。 |
| **同动作通用 Agent** | 完整输入、相同工具/候选/状态读写、同等重新规划与澄清权利，自主输出动作集合。 | 检验框架策略是否超出通用模型在充分接口下的能力。 |
| **完整日志重读 Agent** | 上下文能容纳时直接看同一完整历史，重新推断状态并获取/推荐。 | 排除压缩记忆丢信息造成的虚假优势；长历史另测共同预算曲线。 |
| **共享组件 Waterfall** | 与成熟组合共用解析、状态容量、来源、评分、执行保护，只替换明确声明的决策规则。 | 定位控制机制增量；无法指出替换项时，只能报告系统/参考实现效果。 |

固定候选 RecBot-style、MARS-style 作为任务边界和组件诊断，而不是被故意限制能力的唯一主对手。若将它们补上公共获取模块，名称注明 adapted，并单列补了什么；原论文的分数不搬进同一表。原系统复现与共同组件控制分开报告。

共同条件包括模型与解码、信息可见范围、工具能力、内容快照、状态容量、获取/展示/模型预算、响应时限和执行校验。搜索失败、重试、内容读取、记忆检索和模型评分都计费。总配额一致之外报告实际成本与质量曲线，避免一个方法免费预读内容。

主分析先做三个边界替换：固定候选供给、每次固定执行全流程、只用当前指令与短历史。它们帮助解释全任务要求，不与主表所有方法机械做笛卡尔积。状态冻结/语言删除可作诊断，但不把低能力消融当最强基线。

## 7. 基准怎样覆盖整个范式

### 7.1 必备场景矩阵

| 场景轴 | 覆盖点 | 标注对象 |
|---|---|---|
| 用户输入 | 明确命令、含糊评价、只有行为、命令与旧偏好冲突、普通内容讨论 | 话语功能、指向对象、可支持解释；普通讨论不自动变推荐指令。 |
| 作用范围 | 单条内容、本屏、本任务、某段时间、长期偏好 | 约束范围与生命周期，允许无法判定。 |
| 任务发展 | 延续、细化、切换、并行任务、完成、旧解释纠正 | 当前目标及可允许状态变化；纠错只是其中一类。 |
| 内容供给 | 池内足够、需查询、需换来源/模态、结果重复、不可得、工具失败 | 有效候选、内容缺口、合理获取/保持决定。 |
| 反馈条件 | 明确点赞/反对、评论、停留/滚动、无回应、延迟回应 | 实际曝光与证据强度，不能给所有弱行为强造唯一意图。 |

每类都含无需修改记忆、无需再搜和应当结束的样本，避免只挑“Agent 必须忙起来”的场景。热榜是一个可用获取入口，不被预设为低级基线；没有当前任务时，合适的热门内容也可能有价值。固定 8 轮×每轮 5 条只是起步的受控评测协议，不是范式边界；自然浏览允许不定轮数、不发指令、改变目标和随时结束。

### 7.2 三种证据各回答不同问题

- **真实轨迹前缀上的共同输入评测**：评估理解、状态变化、可接受动作和当时内容支持。允许多个正确动作序列；精确匹配 JSON 只测格式，不测语义成功。
- **冻结可检索环境中的受控分支**：固定同一前缀，改变候选可得性、工具失败或语言范围，测动作依赖与鲁棒性。来源、内容、工具返回可重放；不偷看未来反馈。受控分支的行为反应若是模拟，明确标记。
- **实际曝光后的真人闭环**：参与者看到各条件实际生成的内容，再产生各自反馈。用于测连续有用性、可控感、负担与任务进展。不同策略产生不同轨迹，不能把 Waterfall 获得的后续反馈免费送给基线。

真实固定日志不能提供“另一种从未展示的内容会获得怎样的真人反应”。离线回放可以比较共同前缀下的输出，不能据此估计任意新策略的真人闭环效果。原意核查若在结束访谈进行，必须记录获知时间；不能将它回填为系统当时已知道的状态。

评测至少分四层：语言接地/范围判断，动作有效性与任务适配，状态证据充分性，连续内容有用性与任务进展。获取质量、来源/模态适配、冗余、约束违反、延迟和成本作为解释维度。不能用系统自己的满意度猜测作唯一标签，也不以强迫用户多刷内容定义完成度。

数据文档须给出用户/任务/时间划分、母样本和变体关系、授权范围、去标识处理、来源及内容可再分发条件、标注分歧和不可判定比例。研究资源可以发布可复现索引/快照协议，而不必复制所有第三方原文。这里只规定方法有效性所需信息；不额外启动采集。

## 8. ACL 的语言研究落点

**[提案]** 最清楚的研究问题是：自由表达怎样与浏览行为共同形成一个有范围、可执行、可持续修订的用户意图，而这个意图怎样约束内容获取和推荐。

| 语言现象 | 在 feed 中的可测例子 | 需要观察的后果 |
|---|---|---|
| 指代与省略 | “这个讲法可以，再实际一点。” | “这个”对应哪条曝光，“实际”改变什么属性；获取和排序是否一起响应。 |
| 否定与范围 | “别再给我买相机的，教程可以。” | 排除的是选购用途，不是相机主题全部内容。 |
| 语用与话语功能 | 对文章展开讨论、引用作者观点、直接要求调整推荐。 | 哪些话修改偏好，哪些只参与内容对话；不能一律写入长期状态。 |
| 时间与任务语义 | “今天通勤只看短的”“这件事办完了”。 | 临时要求的结束条件和旧任务降权，后续回到什么状态。 |
| 跨模态指向 | “看图步骤更清楚，别来长视频。” | 用户针对表示方式的要求是否转成可执行来源/模态选择。 |
| 行为解释与修订 | 收藏可能用于比较、保存、替人查询；后来的说明改变含义。 | 保留原始行为，改变被支持的状态及后续行动；不给含糊行为编造唯一真值。 |

因此，ACL 主表除了整体效果，应有按这些现象预先分层的测试与误差分析，并将具体语义错误连接到失败动作和用户后果。使用未见措辞、未见任务及未见用户来检验泛化，避免模型只识别有限命令模板。

[ACL 2027 主会征稿](https://2027.aclweb.org/calls/main/)明确接纳新资源、负发现、使用既有技术得到的语言发现等贡献，也列出 Dialogue and Interactive Systems、Human-Centered NLP、Information Retrieval、LLM Agents 等方向；因此不必为了“像方法论文”强加训练。相关性仍须由对自然语言处理的具体研究贡献体现，不能只靠系统里用了 LLM。录取与论文贡献比例没有可保证的公式。

## 9. 本轮交付与尚未验证项

本稿已固定完整研究对象、最小公共接口、分阶段 JSON、成熟能力归因、强组合基线及三个可验证命题。下一步可直接据此编写环境适配器、场景/标注规范与基线规格；数据细节可扩展为独立工作包，不再默认降为附属贡献。整体工作顺序见[主入口](2026-10-27-agentic-feed-master-plan.md)。

尚未验证：参考控制器能否稳定执行这些动作；自然交互中各难点的频率；真实候选与跨模态内容是否充分；标注一致性；强组合和全日志重读能达到什么水平；持续效用与成本收益；现有方法分数是否真的遗漏重要错误。本文未执行研究性模型评测、作者实现或人体研究，未取得 RecBot/MARS 官方代码，没有将设计例子当作实验结果。

本稿不做穷尽式查新，也不承诺 ACL 主会接收；进入投稿前仍需核查后来出现的直接近邻。风险是做成成熟组件拼接而缺少研究发现：解决办法是把共同基准与强对照真正做出来，并按证据收束主张，而不是继续把完整问题缩成一个预先挑好的小功能。
