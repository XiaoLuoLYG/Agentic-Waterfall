## 1. 固定范围与研究问题

九项实验的唯一总表见 [主方案第5节](../../01-研究主方案.md#5-用哪些实验回答这些问题)：公开基准与模拟一致性一表，跨系统内容评分、盲选与消融单列一表。已有基准为 ClawRec-SimBench、AgentRecBench、MIND-small、KuaiRand-1K、KuaiRec；完整系统主对照仍为 Waterfall、ClawRec-adapted、i2Agent-adapted＋公共检索、通用工具 Agent、固定检索排序。检索取舍见 [来源核查](prior-work-check.md)。

**执行暂停。** 原定对照、可补的候选适配和建议后置的训练在主表中分开标注；新增比较尚未获准执行。盲选保持暂停；下文的采集、预算和demo接入均为设计，不是当前任务。任何训练先核可复用权重、硬件、耗时和预算，不默认本机长训；方法间公平性不要求一律重新训练。RecBot的AIA组件、LLM-SRec训练链及传统模型的参数需求见主方案第5.3节。

分别检验：传统排序能力、完整目录获取能力、具体内容的逐项评分、多轮交互回报与匿名推荐偏好、模拟数据是否可靠。不合成一个总分。RecBot/MARS 进入固定候选诊断，不再额外占用完整真人主表条件。

**当前研究边界：**跨系统盲选与逐系统内容评分是并列评测，两者均隐藏系统身份，分别出结果。Waterfall 的记忆长期保留并随证据更新；本阶段不做跨会话、清空记忆或自动遗忘实验。状态的适用范围和存储寿命分开，需求完成不等于删除历史。

动作格式、引用与执行成功属于运行正确性检查；不同合法工具路线都可以取得好结果。不拿研究者手写的唯一动作序列作为主评分。

## 2. 目标 ID、候选与获取的边界

目标例子：用户后来点赞 `kuairand:1042`《手机跟拍足球》，内容类型 video、tag 足球。标准下一条 ID 匹配比较 `ordered_item_ids` 是否包含 `kuairand:1042`；类型、标题、tag 只作特征，不替代身份。

- **固定候选实验：**标签由评价器保管；把统一候选交给所有方法排序。按协议把目标和干扰项放在一起是测试集构造，不是提前告知哪条为正例。候选展示顺序随机，避免目标恒在第一项。
- **获取＋排序实验：**模型只能推荐实际取得的内容。库里有目标但搜漏，最终算未命中；搜到但未排入前 K，同样未命中。不能仅在“已经搜到”的样本上报告最终 Hit。
- **目录本来不含目标：**依据事前固定的目录与目标选择规则报告覆盖率，所有方法使用同一可评样本集合；不能看过系统结果再挑样本，也不为单个目标临时扩目录。
- **我们新数据的主评价：**不规定唯一正确 ID。另一条足球内容同样可被本人选中；这里评价的是当前偏好，不是是否重现旧日志。

获取诊断可报“目标进入已获取候选的比例”及“已获取时排入前 K 的比例”，但最终 Hit 分母保持全部可评样本。例如 100 题取回 80 题目标、最终推荐到 70 题，最终 Hit=70%，不能只报 70/80。

## 3. Waterfall 怎样跑已有数据

### ClawRec-SimBench：正式加入最直接的外部比较

2026-10-28 修订：此前列作可选的决定取消。主比较为 Waterfall、ClawRec-adapted 与同工具通用 Agent，所有方法在同一次运行条件下重跑；论文已发表的分数只作出处，不直接与我们当前的数值相减。

**数据怎样来的。** ClawRec 先生成模拟用户的五个生活事件及意图，再由 GUI Agent 在来源网站执行并保存观察到的行为。每事件最后一步藏起来，前面实际取得的记录给被测系统。它提供真实网页上的合成行为轨迹；我们自采再补本人愿看与实际使用结果。[官方数据说明](https://github.com/RUCAIBox/ClawRec/blob/main/clawrec-simbench/README.md)

**怎么运行。** 为每个用户创建独立工作区，只把 `input/` 给方法；`private/` 仅由评价器读取。同一用户的五事件依次执行，保留该方法自己的状态，换用户才清空。第二个事件开始，可见文件仅补前事件最后一步及当前前四步，更早信息通过已有状态保留。[复现流程](https://github.com/RUCAIBox/ClawRec/blob/main/docs/reproduction.md)

**怎么打分。** 根据隐藏的下一步需求，对各方法推荐的内容给任务相关性 1–5 分；不同 URL 只要能支持同一需求也能得分。主报 Hit@20 与共享评价池上的 NDCG@20；用户状态是否符合已知行为作为诊断另报。所有方法的前 20 条合并去重，评分时隐藏方法名，再把分数映射回各自顺序。该实验用模型评分，不写成本人选择。[原论文 §4.1.2](https://arxiv.org/html/2607.23779v1#S4.SS1.SSS2)

**具体接法。** 映射公开行为到统一输入，把来源白名单和预算传给工具层；最终输出最多 20 条，不能沿用个人 demo 的六条上限。共同工具版让三方法访问同一来源后端，沿用该任务的 10 次搜索任务预算并展开统计实际请求，内容快照随运行保存。工具替换、模型版本与任何预算差异都记录为 adapted；原作者环境的完整复现另列。开发用户用于确认适配和评分说明，测试用户的隐藏需求不调提示词；按可核实的发布 split 运行，无对应清单时公布按用户固定的本地 split。

**评分代码要核对的一处差异。** 2026-10-28 读取的[当前聚合脚本](https://github.com/RUCAIBox/ClawRec/blob/main/evaluation/trajectory/aggregate_trajectory_judgments.py)在 `compute_metrics_from_rels` 中用本列表相关性排序计算 IDCG；论文要求跨方法共享池。实施时保留原脚本结果作对照，主比较按论文的共享池计算并注明评分器改动，不能把两种 NDCG 混在同一列。

10 月 22 日固定提交的核查找到 42 个公开用户工作区、210 个事件，论文实验表规模不同；这次未重新完成全树计数，不沿用旧数字冒充当前可运行量。下载后按实际完整案例、版本和 split 报告规模，文件数不妨碍本轮将它列为必做。[历史核查](../archive/prior-work-check-20261022.md)

### AgentRecBench：正式加入标准 Agent 推荐对照

采用 NeurIPS 2025 正式论文、官方任务包与对应代码。数据覆盖 Amazon、Yelp、Goodreads，提供经典、兴趣变化、冷启动任务；原任务每题 1 个历史正例和 19 个未交互候选，主报 HR@1/3/5。兴趣变化通过不同历史窗口构造，分别报告长短窗口；不把它等同于真人反馈驱动的连续信息流。[论文](https://papers.neurips.cc/paper_files/paper/2025/file/e2d6f7249add096e26679eade1b4cc6f-Paper-Datasets_and_Benchmarks_Track.pdf) · [任务包](https://huggingface.co/datasets/SGJQovo/AgentRecBench)

**接入流程：**读取原 task 与当时可见资料 → 把用户、物品、评论查询工具接给 Waterfall → 方法自行取证并形成状态 → 输出原候选 ID 排名 → 官方评价器计算 HR@1/3/5。隐藏目标只给评价器；没有真实指令就留空，不按目标编指令。这里 acquire 获取候选相关证据，不向原题加入新的候选。

**对照与版本：**以官方推荐 Agent 基线为最低对照，优先复现论文强基线 Baseline666；代码可用性和实际复现版本在开发阶段确认，不能用论文数字冒充本次运行。与 Waterfall 使用相同底座、可见信息及资源上限；按领域、任务类型分别汇总，保留无效输出与失败。官方任务与 groundtruth 分开加载，按实际发布 split 运行；无完整划分时，事前按用户固定本地划分并标明。不同独立任务不带入其他题的隐藏答案。[官方入口](https://github.com/tsinghua-fib-lab/AgentSocietyChallenge/tree/final) · [评分器](https://github.com/tsinghua-fib-lab/AgentSocietyChallenge/blob/final/websocietysimulator/tools/evaluation_tool.py)

已核对论文、数据说明、仓库入口和HR评分代码；截至2026-10-29，仅有Amazon短历史3题诊断及候选详情漏传问题的离线修复，尚无跨领域正式方法比较。其余四套基准继续保留，AgentRecBench补充标准Agent推荐证据。

### MIND：保留原曝光排序任务

输入采用每条 impression 的历史点击 ID、关联新闻信息与该次全部候选；删除本次 0/1 点击标签。没有原始命令或明确画像就留空，记忆只能从当时可见的历史自行构建。新闻用发布包实际提供的标题、摘要等字段，不依赖今日网页内容补齐旧新闻。[官方字段](https://github.com/msnews/msnews.github.io/blob/master/assets/doc/introduction.md)

Waterfall 在固定候选模式运行，获取工具不开放到候选之外，最终 recommend 必须给出全部候选的无重复排列。适配器按原 impression 的候选顺序生成 rank 数组，调用官方 evaluate.py。评分为每个 impression 的 AUC、MRR、NDCG@5/10，再按官方方式汇总。只交 top-1 不足以完成这个评分。[官方评分代码](https://github.com/msnews/MIND/blob/master/evaluate.py)

**默认先做 MIND-small 本地可复现实验：**官方 train 按全局时间划前 80% 用于训练、后 20% 用于调参（同一时间戳不跨边界）；官方 validation 在本项目封存为本地测试。名称写明 `MIND-small / local split`，不冒充官方 hidden-test 榜单。训练字段、全局统计与已学习参数均不读取本地测试答案，测试时自己的此前可见历史仍可读。正式外部榜单比较再使用 MIND-large 官方 train/dev/test 与可用的官方提交流程；未经实际提交不报告官方测试成绩。[数据版本入口](https://msnews.github.io/)

原定对照为NRMS、固定内容排序与Waterfall，热度只作评分烟测锚点。主表另列ClawRec候选版、i2Agent、通用Agent、MARS与RecBot为待确认补充，不能据此自动扩跑；它们只检验候选排序，不能从MIND推出完整搜索或用户指令理解能力。NRMS先核匹配权重，需训练时另定资源，分别报告训练与推理成本。所有方法使用同一候选、可见信息与评测程序；共同子集必须在看标签和结果前固定，并明确标为subset。

当前保留的固定1000题中，Waterfall与TF-IDF已生成输出，NRMS已中止、未生成测试排名，尚未统一评分；Waterfall的695有效交付／305失败是运行情况，不是推荐效果。若加入多阶段Agent，须先确认统一流程与预算，不能把新增运行直接与旧的单次调用结果拼成公平比较。

模型无效输出先记录失败；不查看标签地使用预先声明的全同分后备提交，使该题仍进入评分，并单独报告无效输出率。正常输出不得靠目标标签补全排序。

### KuaiRand：固定本文协议，使用传统指标

KuaiRand 有行为日志与普通/随机曝光，但没有唯一官方算法评测切分。下面是本项目的公开协议，不能与其他候选和切分上的论文数字直接横比。[官方数据说明](https://kuairand.com/)

| 项目 | 第一版默认设置 |
|---|---|
| 版本与切分 | KuaiRand-1K；所有用户共同训练窗 2022-04-08 至 04-21，开发窗 04-22 至 04-28，测试窗 04-29 至 05-08；使用数据 date 字段划窗、time_ms 排序 |
| 内容目录 | 训练窗已实际出现、且有可用内容元数据的视频构成固定目录 C；冻结 ID 与字段版本，不用未来点击次数/整月统计生成热度 |
| 目标定义 | 每位用户每个开发/测试窗，在普通与随机曝光中各取第一条此前未曝光、long_view=1 的视频为 target；先按此规则选目标，再检查目录覆盖，不改选更容易的目录内目标 |
| 输入与候选 | 提供目标发生前已经结束的行为及可见元数据；可评目标＋从 C 采的 100 个不同对照项，排除目标及该用户此前所有已曝光项，固定随机种子并打乱位置；候选不足 101 的样本事前标记不可评并报告数量 |
| 指标与对照 | Hit@10/20、NDCG@10/20；单目标 Recall 与 Hit 相同不重复列。比较 SASRec、LLM-SRec 与 Waterfall；随机/普通目标分层报告 |

`long_view` 按官方时长规则，不等于人工“喜欢”。对照项未获该用户反馈时只是这个 next-item 测试的干扰项，不能写成真实点踩，也不拿它们直接算点击预测的 0 标签。推荐目录覆盖率与各原因排除数量同时报告。按全局窗口冻结训练，避免“逐用户留最后一项”时其他用户的训练记录来自测试的未来。

SASRec 的训练目标采用训练窗内 long_view 正反馈序列的下一项预测；其他原始行为作为可用记录保留，能利用它们的方法可按自身机制使用。若另做点赞任务，训练/目标统一改用 is_like，单独出表，不能一边按观看训练一边混称点赞命中。候选特征和原始历史的可访问范围对所有方法一致。

SASRec 作者实现采用留出目标与采样候选计算排名指标；我们沿用这种任务形式，但使用上面声明的时间划分和候选顺序，而不是宣称重现作者原数据结果。[作者实现](https://github.com/kang205/SASRec)

如目标时长跨越下一决策时刻，只在观看结束后把完整时长加入历史；不能用当前尚未完成的长观看标签。当前测试目标及同次结果始终由评价器保管。测试窗口中更早已经发生的行为可作为共同日志前缀，不据此宣称任一新策略真实产生了这些反馈。

### KuaiRec：完整目录获取＋多正例排序

采用 [官方数据及文本补充](https://kuairec.com/)；big matrix 训练与构建历史，small matrix 评价。原论文已将 small 的用户–视频交互从 big 排除，导入时再次检查 `(user_id, video_id)` 不相交。[原论文 §§3.1.2–3.1.3](https://hexiangnan.github.io/papers/cikm22-kuairec.pdf)

- **切分：**small 的 1,411 用户用 seed=42 固定排列，前 282 人为开发，其余 1,129 人为测试。模型训练只用 big；开发 small 可调参，测试 small 只进评分器。这是静态隐藏偏好任务，不声称 big/small 是严格先后时间窗。
- **目录：**small 的 3,327 个视频，统一文本/类别和版本。每用户未观测的约 0.4% 条目用公共 eligibility mask 排除，不填成负反馈。内容文本是后来发布的固定补充，不冒充 2020 年实时网页。热度只由 big 计算，不使用全期行为统计。
- **运行：**Waterfall、ClawRec、固定检索排序在共同目录获取最多 100 个不同候选，最后交 10 条；只能推荐实际取得的 ID。LightGCN 用 big 训练，做传统全目录排序对照。全目录打分与工具获取的计算成本分别报告，不强迫低成本矩阵打分模拟浏览器调用。
- **标签：**每用户所有 `watch_ratio > 2` 的可评视频均为正例。这是累计观看比例标签，不是点赞；沿用作者原论文阈值。画像、历史、检索索引不能读 small 反馈。
- **评分：**主报 Recall@10、NDCG@10；辅助 Precision@10、已获取候选的 Recall@100。理想排序依据整份可评目录的全部正例，不只依据已取回的正例。无正例用户的 Recall/NDCG 不参与均值并单列数量，Precision 保留。

例如用户有 40 个正例，前 10 条里有 6 个：Recall@10=15%，Precision@10=60%。任何有正反馈的足球视频都可得分，不要求找回唯一目标。未取回的正例仍在 Recall 分母里。

传统对照代码：[LightGCN](https://github.com/gusye1234/LightGCN-PyTorch)、[LLM-SRec](https://github.com/Sein-Kim/LLM-SRec)。LLM-SRec 在 KuaiRand 用同一 long_view 序列和切分预训练 SASRec，再按作者训练入口适配；它是训练型序列基线，单列底座与训练成本，不包装成原生完整 feed Agent。

KuaiRand 自主获取扩展、额外点击概率/时长预测不列入本版必做清单；所需证据分别由 KuaiRec 和自采数据承担。字段与缺失处理详见 [数据集参考](dataset-fields.md)。

## 4. 新数据集怎样建

### 数据单位与内容世界

工作名 Agentic Waterfall Feed Benchmark。最小评测单位是 `用户＋截止点＋内容环境＋方法运行＋本人判断`；连续评价单位是一个指定系统的独立会话。

| 归档部分 | 保存内容 |
|---|---|
| 用户与前缀 | 去标识用户 ID、split、原话、真实行为、本人显式资料、每条信息可见时间；保留原始事件，方法自己形成记忆 |
| 可查询环境 | 内容 ID、规范 URL/来源、文本或可播放媒体/转写、类型、发布时间/可用时间、快照 hash；索引与检索器版本、来源能力、时间门控 |
| 方法运行 | 模型/提示词/适配器版本、资源配额；每次输入、原始输出、解析、工具请求和实际结果、状态版本、最终推荐 |
| 客户端结果 | 真正曝光的位置与时间、打开/阅读/播放/赞踩/收藏/评论、观察是否结束、退出或任务完成原因 |
| 私有评价 | 对比双方与内容映射、随机位置、本人盲选、逐项内容评分；隐藏目标及答案不进入当前决策 |

内容世界应能响应新查询。首版按用户选择的真实兴趣领域，从至少三种来源取得可保存快照的图文与短视频内容；来源数量是采集配置，非每次强制混源。种子主题来自试采及开发用户，另纳入通用热门与无关候选；不要只收 Waterfall 的查询结果，也不按照测试用户的隐藏答案补库。记录规模、来源/模态分布与可用率，试采后固定首版目录和规则。

首版主对比用冻结索引与内容快照保证查询机会一致；实时互联网作为独立的版本化补充批次，保存实际响应。只有旧查询缓存无法让新算法自由检索；可重放工具也不等于可以重放新策略下未知的真人行为。这一区分与 [RecSim 的交互环境设计](https://research.google/blog/recsim-a-configurable-simulation-platform-for-recommender-systems/)一致。

### 两种可复用入口与标签范围

**完整获取：**每个截止点运行主表五系统，各自取得并提交 5 条；内容可以不同。所有结果提交后，再混合匿名卡片逐项标注，保存各方法原来的名次。标签以 `(user_id, context_id, item_id)` 为单位，同一时刻重复内容只标一次；跨轮的旧分不能当新分复用。

**共同评价池：**合并上述真实输出并去重，完整标注后，可计算共用理想列表的 NDCG@5；这是相对于这批评价内容的获取＋排序结果，不是对整个互联网的 Recall。若再把这个已冻结候选池提供给 Waterfall、RecBot、MARS 重新排序，则是固定池排序诊断，两种实验分表。

未来方法从公共目录取得池外内容时，需要补标并重算共同评价范围；不能把未知内容算负例。终止比较区的标签默认不进入各方法历史；独立连续会话中的评分则按第 7 节，在发生后发送给相应策略。

## 5. 固定方法怎样接入

入口一 `rank(prefix, candidates) → ordered_item_ids`，适配器包成 recommend；入口二 `step(observation, tools, budget) → actions`。公共层只转换调用、验证 ID、记账，不替任何方法理解用户或建画像。

| 方法 | 保留原能力 | 本文适配 |
|---|---|---|
| Waterfall | 三类输入与环境驱动获取、推荐、更新 | 公共内容、工具与记录接口 |
| ClawRec-adapted | 事件证据、时效状态、来源规划、获取、互补选择、反馈和有界补查 | 将浏览器获取传输接到共同索引，保留自身查询和来源决策 |
| i2Agent-adapted＋公共检索 | 画像生成、对具体推荐的反馈提取、画像更新与 rerank | 公共检索供候选；按论文维护自己的 profile，不能读当轮待预测答案 |
| 通用工具 Agent | 自行观察、查询、记忆、重试与停止 | 同底座和工具，给中性任务说明，不给 Waterfall 的推断状态或轨迹示范 |
| 固定检索排序 | 固定查询模板、获取次数、历史特征与内容排序 | BM25＋BGE-M3 检索，融合后 BGE-reranker-v2-m3 排序；无自选工具流程 |

公共检索记为 R0：从原始指令、最近原始查询、本人明确资料及历史内容按固定模板构造查询。BM25 和 BGE-M3 在全索引各取前 100，按 RRF（常数 60）融合，最多保留 100 个不同候选；最终排序前五。无个人信号时用开发阶段冻结的热榜。候选上限、历史截断和模板只在开发集调节，统一记入工具/成本预算。[BGE-M3](https://huggingface.co/BAAI/bge-m3)、[reranker](https://huggingface.co/BAAI/bge-reranker-v2-m3)

i2Agent 以[论文](https://arxiv.org/html/2502.14662v4)和[论文指定代码](https://github.com/agiresearch/iAgent)为依据。作者代码的短历史、逐样例 profile 构建及小批量调试入口，不能原封不动冒充连续会话实现；剥离原测试循环、接入可见反馈和持久状态属于显式适配，单列改动与机制检查。

**诊断对照：**RecBot 保留正负/硬软约束、偏好合并与工具链；其 Matcher 含语义与 AIA 协同路径。若只实现语义路径必须标 `semantic-only`，不把它冒称完整 RecBot。MARS 保留 event/preference/profile 维护及基于自产画像的候选打分。两者仅看同一前缀与共同候选，不读取 Waterfall 私有状态。[RecBot](https://arxiv.org/html/2509.21317v2)、[MARS](https://arxiv.org/html/2605.14401v2)

各方法从同一原始前缀建立私有状态。所有 Agent 用同一底座、解码与资源上限；传统/训练型模型正常使用训练集，另报训练成本。作者原设置重跑与本任务 adapted 结果分开，不直接搬论文分数进表。当前核查代码入口不等于已运行复现。

## 6. 每条实际内容的标签与单系统得分

**本节列出两条并列评测。** 内容评分可独立给单个系统计分，跨系统盲选记录相对偏好；两者均为正式评测、均隐藏方法身份。连续多轮是内容评分的执行方式，消融是比较版本的设计，不另建替代这两条的评分体系。

本版取消所有系统级问卷，包括 ReSQue/UES。人的标注对象是具体内容：当前这条内容是否合自己口味或有价值。标签暂定为 0 不感兴趣、1 一般、2 喜欢、3 很喜欢；无法判断另记。四级锚点、展示材料及试采理解要在正式采集前固定，不能看结果改阈值。

评分基于可实际查看的内容；统一预览规则、可打开的正文/视频等访问条件，并保存用户看到的快照及实际展开情况。只看标题不能被记作读后评价。不要求先有明确任务。逐项反馈的采集不意味着把它宣称为客观效用；它提供清楚的 item 级测试标签。

**每轮主要得分为 DCG@5，采用线性 gain。** `DCG@5 = Σ[k=1..5] r_k / log2(k+1)`。直接使用原始 0–3，不按“≥1”生成比例。总分相同的两批内容，把高分内容排前面会有更高 DCG。使用标准定义与实现，并保存 gain 配置。[DCG 文档](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.dcg_score.html)

DCG 可以独立给一个系统算，不依赖其他系统输出。NDCG 则需要同一评价范围的理想排序；若使用各法自己五条排序当 IDCG，全是一般内容也可能得 1，不能这样评价整体获取能力。[NDCG 定义](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.ndcg_score.html)

固定候选诊断以及自由获取后的共同完整标注池均可用 NDCG，但分别写明是否预先共享候选。每个用户先求分，再跨用户汇总，按用户成组计算区间。同一系统在不同轮的 DCG 不合并成一个没有轮次的排行榜。

### 并列评测：跨系统盲选

同一时刻的输出进行 A/B/都想/都不想的选择，报告四类分布与方法对差值。主表按用户与方法对汇总；方法身份隐藏、位置随机。重复内容单列，不能造胜负。失败、无法判断和未答分别保存，不能只留下双方交付且有明确偏好的题。评分产生在真正连续使用期间；跨方法的混合评分与盲选放在终止比较区，不插进某条独立交互轨迹。

## 7. 真正连续的三轮评价

首版试采用 3 轮×5 条，共 15 个推荐机会；这是待试采确认的预算，不是论文规定。主对照 Waterfall 与 ClawRec-adapted 分别运行自己的会话，方法次序在用户之间平衡；其他主表方法先参加同一截止点的内容评价。界面与工具预算一致，初始原始资料和提供历史规则一致，各自形成状态。

每轮按下列顺序执行：

1. 仅给当前时刻已可见信息；Agent 可以更新状态、调用来源工具，再提交实际取得的 5 条及顺序。
2. 固定本轮输出，再展示给本人逐条评分。原话、赞踩、收藏等正常操作也保存；不能在评分过程中改掉已提交列表。
3. 本轮反馈提交后，以原始标签和原话建立带来源的已发生事件，记录 `feedback_available_at`，只发送给这段会话的当前策略。未来标签与其他策略候选的评分不可见。
4. 当前策略自行更新状态、获取/重排下一批。重复到第三轮；记录全部工具回执、状态前后和展示顺序。

这里明确允许上一轮内容评分进入下一轮，这是研究中的显式反馈，不是答案泄漏；当前待评分推荐的答案仍不可提前给。底座模型和策略在测试阶段不利用测试用户标签重新训练，但可以按被测算法正常维护记忆。

**连续主指标采用累计回报。** `R = Σ_t Σ_k r_(t,k)`。另外画各轮平均 reward 与 DCG，用来观察随反馈变化的表现，不额外起一个“适应分”。KuaiSim §4.2 使用整段即时回报之和及单轮平均；我们将即时回报定义为真人内容标签，不能冒称其原始 reward 就是这套标签。[KuaiSim](https://arxiv.org/html/2309.12645v1#S4.SS2)

演算：三轮 `[0,1,2,0,1]`、`[3,2,2,1,2]`、`[3,3,2,3,2]`，累计回报 `4+10+13=27`，每轮均分 `0.8/2.0/2.6`，DCG@5 `2.018/6.466/7.959`。上升只能描述这段轨迹；更新是否造成改善，要做第 9 节对照。

### 缺失、重复与停止

- 每段的默认内容资格排除已经展示的规范 ID，重复提交消耗对应位置、不再次获得新内容收益；用户主动要求重看单独记录。不同轮的标签不复制，尤其需求已改变后。
- 系统超时、空输出或不足 5 条，对应机会记零交付收益，原始 grade 保持空，并保留失败状态；并不是伪造一个人的 0 分答案。
- 正常停止统计实际累计回报和已交互深度，不给未看内容伪造偏好。已展示而漏标仍是未知。固定 15 位分析保留全部分配与中断：除实际回报外，对未知槽位可按每项 0–3 给出上下界，并报告缺失；不只留下答满 15 条的人。
- 点击和时长只是辅助记录；当前外站返回时长不当实际阅读时长。成本和交付时间单列，不混进内容回报。

## 8. 采集规模、划分与执行预算

**预算草案：8 位试采＋80 位正式参与者。** 先用单系统三轮验证流程和负担，再确定正式量。20 开发/60 测试仍为预算起点；需要训练时开发分 12/8。试采不入正式测试。

| 部分 | 暂定规模 |
|---|---|
| 连续会话 | 每人两个系统、各 3×5，共 160 段、至多 2,400 个评分位置；测试 120 段、1,800 位置，AB/BA 各 30 人 |
| 同一截止点评内容 | 每人五方法各 5 条，去重前至多 25 个标签，共至多 2,000；测试 1,500。混合评价放在连续会话结束后 |
| 盲选 | 当前截止点 W 对四个对手，共 320 对；测试 240 对；记录题序及实际有效量 |
| 固定池排序诊断 | 复用同一截止点已完整标注池，给 RecBot/MARS 等重排；原则上无需新增标签 |
| 五组首批消融与重复题 | 从事前选定子集增加，按所测方法和轮次单独核算；不假定可无成本复用另一策略的未来标签 |

前两行最多 4,400 个内容评分位置，实际量因重复、缺交和未答分别记录；这是工作量上限预算，不是样本量论证。无历史启动、只有行为、自然指令与需求变化作为事前安排的情境；普通浏览不强迫用户完成目标。

这些人数是预算起点，不是“已证明足够”。试采后先确定要检测的实际差异、用户级方差、所需人数与失访预留，再冻结正式 N 和停止规则；不能边看测试优势边加人或停招。参与者以有信息流使用经验、对所选场景有真实需求的成年人为起点，招募来源与覆盖范围随数据报告。实际采集前完成本人同意、去标识记录与退出处理。

**开发阶段的共同资源起点：**每次下一步任务最多 10 次实际检索/详情请求、总共返回 100 条不同候选、最多显示 5 条；所有 Agent 使用同模型版本与解码设置。每次新决策最多 32k 模型输入＋输出 token、60 秒交付截止。记忆长期保存；模型上下文上限不是记忆存储上限，不因此删除长期记录，实际读取与输入截取规则需记录。原始共同前缀从最早提供的 checkpoint 顺序处理，预热消耗单列并计入总成本；不借此免费预先运行 Waterfall。

这些资源数是待试采验证的开发默认值：若不足以执行某个方法的基本机制，在开发阶段统一调整后冻结，并加一档宽松预算作敏感性比较。按真实工具子调用计费，一个封装动作内部多次检索不能只算一次。主表在共同上限下比较，不强制所有方法恰好花一样多的钱；同时报告质量—成本关系。

固定候选/公开数据任务采用各自输出数量：KuaiRec 最后交 10 条；MIND 要完整排名，不能误用当前 demo 每次至多 6 条的上限。不同模态实际给模型哪些文本、转写、画面与元数据保持同条件可访问，并披露模型能力差异。

## 9. 收益归因：五组首批消融

完整 Waterfall 是共同参照，每次只改变一个功能。固定底座、解码、可见信息规则、初始内容、推荐机会和资源上限；实际用量可以不同，单列成本。跨系统盲选和逐系统内容评分并列；消融只规定比较版本。第一批所有版本先做内容评分，对关键对照补盲选。

| 版本 | 保留什么、只改什么 | 检验 |
|---|---|---|
| 去用户表达 | 隐去指令、评论、纠正和相关对话；从其余允许来源重建实验状态，阻断衍生记忆、查询和特征泄漏 | 显式表达的增益 |
| 去行为记录 | 隐去曝光、打开、停留、赞踩、收藏等行为；从其余允许来源重建实验状态，阻断衍生记忆、查询和特征泄漏 | 行为证据的增益 |
| 固定行动流程 | 保留相同状态、获取和排序模块；每轮固定执行更新→获取→排序，查询与内容选择仍由原模块完成 | 按需选择行动是否优于固定步骤 |
| 关闭新内容获取 | 与完整版共享起点已有的充足候选；后续禁止 acquire，状态更新与排序保留 | 新获取是否改善推荐 |
| 冻结状态更新 | 保留同一初始长期记忆和已发生的新反馈；只禁止后续持久状态写入 | 更新用户理解是否改善后续推荐 |

**固定流程。** 预先固定步骤和获取预算，不允许按结果临时改变流程；不替换底座或把排序器降级。与完整版比较内容得分、累计回报和真实执行成本。

**获取。** 两版本初始候选相同，并足以覆盖整段推荐机会；无获取版本可以继续在其中重排，避免仅因内容耗尽产生机械差异。完整版允许获取新候选。单步比较配对 DCG；多轮分别真实运行并比较累计回报。

**更新的一步配对。** 两版本到达同一变更前状态，再给相同新反馈，仅禁止一方持久状态写入；它仍看到新反馈。各自提交下一批，匿名混合内容由本人标注，比较配对 DCG 差。两版本都可能从可见原始历史重新推断偏好，因此该实验检验持久状态更新的增益；不能故意隐藏冻结版的当前反馈。

**连续收益。** 各版本从相同起点规则分别实际运行，平衡顺序。推荐不同后分别采集其产生的真实反馈，不复制另一策略的未来轨迹。报告累计回报、每轮均分与 DCG；分数上升本身不当作更新带来收益的证据。

**输入来源隔离。** 去表达、去行为均为第一批必做，初始状态按允许来源独立构建，不能沿用已吸收禁用来源的完整系统摘要。独立采集的画像不自动删除；画像字段来源不明时先核查。评分标签始终供评价器使用，不能绕过被禁用通道重新喂给系统；固定候选任务的题面、候选集和评价标签不随消融改变。没有对应输入的公开基准不用于声称该项消融有效。

**第二批可选：**去画像。跨会话、清空长期记忆和遗忘机制实验暂不开展。输入消融隔离信息来源并不等于产品遗忘：各版本的允许记录仍持续保留，需求完成、状态修正只改变当前适用性。

**状态事实诊断。** 对本人明确确认过的事实设置当前答案，例如“已买好电脑”；在后续时刻用只读副本检查事实判断，计算 Accuracy。各方法保持原状态格式，不把 Waterfall 的 JSON 当唯一答案。借鉴 LongMemEval 的 knowledge updates 设计定位错误，不新增一套必跑基准，也不替代推荐得分。[原基准](https://github.com/xiaowu0162/LongMemEval)

主比较预先指定 Waterfall 对 ClawRec：跨系统盲选报告四类分布及选择占比差；逐系统内容评分报告同截止点 DCG@5、连续累计回报与逐轮曲线。两条结果分别解释，不合并总分。其他对照、消融及情境另报效果。按用户成组 bootstrap 95% 区间，多项显著性声明采用 Holm 校正；保留原始标签、方法/环境版本和失败/缺失记录。

## 10. 模拟用户一致性、扩量及后续入榜

### 相同输入，预测本人而非泛泛“像人”

模拟器只读截止点前的本人资料、历史和真实可见页面；未打开时只给预览，打开后才给正文/媒体。未来行为、待预测评分、算法身份均不提供，也不能从答案反推 persona。输出与真人相同的 0–3 内容评分、四类盲选以及打开/跳过/继续/修改需求/满意结束/不满意退出；由环境执行动作，模拟器不编工具结果。

模拟器拟合、示例及 persona 规则学习只用 12 位训练用户；8 位验证用户只选择配置、阈值和通过规则，不把其答案作为生成训练数据的示例或拟合目标。使用预先选定方法记录校准后冻结。测试用未参与校准的 60 人，并把**完整的通用工具 Agent 方法家族**留出模拟器校准（其开发标签不用于调模拟器，系统本身仍可正常开发）。一步评分/选择一致不自动推广到多轮交互；完整轨迹需另验。同一推荐模型兼任模拟器不构成独立证据；参考答案来自真人。

| 检验 | 实际计算与对照 |
|---|---|
| 个人判断 | 同人同历史预测 0–3 内容标签、四类选择和下一动作；评分主报 MAE 并列等级混淆，选择/动作报准确率及宏平均 F1；若输出概率，另报 Brier 误差 |
| 是否真匹配本人 | 比较正确 persona、去掉个人信息、同任务类型错配他人 persona/历史，以及开发集条件多数类预测；逐人求分，冷启动/需求变化分层 |
| 真人自身稳定程度 | 重复题换顺序、左右并记录间隔；首次答案为主标签，重复只作一致性参照，不剔除判断变化的用户 |
| 每系统分数和效果差 | 在同一用户/内容上比较真人与模拟的 DCG@5 及方法差值；完整轨迹另比累计回报与各轮曲线，盲选分布和选择占比差单独验证；报告误差与用户级区间。五系统排序相关作辅助；两个连续系统只比较差值 |
| 自由连续轨迹 | 相同起点让系统＋模拟用户独立运行，不继续灌真人未来反馈；比较打开/拒绝/停止、情境变化后的反应及会话结果；不要求逐字复刻未来语言 |

模拟器不能因总体“喜欢比例”相同就通过，也不能用排名相关替代个体预测。[NAACL 用户模拟评测](https://aclanthology.org/2024.naacl-long.83/)按不同用户行为分别检验；[SimulatorArena](https://aclanthology.org/2025.emnlp-main.1786/)区分实例、分组和系统层；[Agent4Rec](https://arxiv.org/html/2310.10108v2)报告在低偏好比例时仍过度接受的偏差。这些是协议依据，不是 Waterfall 已达到的一致性结果。

**通过规则在开发阶段冻结：**先定生成数据用途和最小有意义系统差距 δ，再设可容忍差值误差 ε≤δ/2。正式测试要求主比较差值误差的 95% 区间落入 [−ε,ε]，且个人预测优于无画像/错配画像与统计基线。例如要区分累计回报 4 分的差距，可取最多 2 分误差；DCG 与选择占比分别使用自己的单位；这是设计示例，不是通用标准或现有结果。一步判断有效时用于一步标签；完整轨迹另外验证。真人重复一致性提供尺度，不当成绝对上限。

连续模拟采用与真人相同的 3×5 推荐机会预算；若另做等时扩展，需从开发真实阅读/反应时长固定时间模型。不能把 LLM 运行耗时或它生成的“看了三分钟”当成用户阅读时间。

### 验证扩量是否有用

固定一个小型 LambdaMART 排序器及其特征（BM25/BGE 分数、历史内容相似度、来源亲和度），比较三个训练集：①真人训练数据；②真人＋未校准 persona 模拟数据；③真人＋校准模拟数据。②③生成数量、上下文、候选和计算预算相同；另画样本量曲线，预先固定 1×/5×/10×真人训练标签量。

训练只使用 12 位训练用户和允许的合成 persona/情境，8 位验证用户调参，最后 60 位真人测试评分；不得用测试用户 persona 或未来反馈生成训练样本。主测试用留出真人的完整候选标签算 NDCG/DCG，并检验盲选对中是否排对胜者；训练复用原始 0–3 标签，双方都选/都拒绝不伪造顺序。它验证生成数据的训练价值，不要求 Waterfall 主框架改成训练型系统。[LightGBM 排序目标](https://lightgbm.readthedocs.io/en/stable/Parameters.html#objective)

全部合成记录标 `origin=simulated`、生成器版本、seed、persona 来源、输入截止点；真人记录标 `origin=human`。一位真人的多个模拟 seed 不增加真人样本量。

### 发布与后来方法接入

发布内容目录/可重建清单、原始前缀、统一 ID、运行器/评分器、split、候选池、失败记录与训练/开发标签；测试答案由评价端封存。新方法排固定池可直接评分；自主获取产生新内容时补本人判断。回访注明新的判断时间；不能回访时用新用户和固定参照系统重跑成新批次。普通标注员不冒充原用户，旧赢家也不能推出其他两条内容的胜负。

## 11. 指标的短解释与演算

标签与指标分开：MIND 的 1/0 是点击/未点击；KuaiRand 是对应行为与时长规则；人的逐项愿看标签是另外一种标签。ClawRec 用留出下一行为的任务支持度 1–5，测试由校准后冻结的 LLM judge 评分，Hit@20 要求至少一条 ≥3；并非严格命中同一 URL。[ClawRec 指标](https://arxiv.org/html/2607.23779v1#S4.SS1.SSS2)

**Hit@K：**前 K 条至少一个正例就记 1，否则 0，再跨样本平均。100 题 70 题命中即 70%。**Recall@K：**找回正例数/全部已标正例数；4 个找到 2 个是 50%。**Precision@K：**前 K 条中正例比例；前三条有 2 个是 2/3。[标准实现](https://github.com/RUCAIBox/RecBole/blob/master/recbole/evaluator/metrics.py)

**NDCG：**当前排序得分除以同一评价范围内的理想排序得分。`DCG@K=Σ g(标签)/log₂(排名+1)`；自采本版固定 `g(r)=r`，其他数据按各自原协议。以点击标签 `[0,1,1]` 为例：DCG=`0+0.631+0.5=1.131`；理想 `[1,1,0]` 得 `1+0.631=1.631`；NDCG@3≈0.693。只有一个正例时，排第一得 1、第三得 0.5。[MIND 实现](https://github.com/msnews/MIND/blob/master/evaluate.py)

自采标签为 0–3，固定线性 gain；不阈值化成愿看率。共同池全部为 0 时，NDCG 记 0 并报比例；未知先补标。MIND 原任务使用原评分处理，不能擅改后仍叫官方结果。MIND 的 MRR 是所有点击项倒数名次的均值，与某些工具只算首个正例不同。

用户仅选“最想看的一条”，不能推出其他内容都不值得看；若增加开放获取的 NDCG，应把各方法返回内容合并去重后逐项标注，使用共同理想排序并冻结评价池版本，新增内容后相应重算，不能把未判定直接算 0。[NIST 关于评价池覆盖的研究](https://www.nist.gov/publications/bias-and-limits-pooling-large-collections)

**推荐另一条足球内容：**严格历史目标 Hit 可以为 0，当前真人盲选可以胜出；两者答案不同，不能把选择得分直接改名 Hit@1。跨系统盲选与逐系统内容评分并列，前者的选择不能替代后者的内容标签。
