## 1. 三组实验分别证明什么

| 实验 | 共同条件 | 不同方法可以改变什么 | 主要结果 |
|---|---|---|---|
| 传统数据、固定候选 | 同一数据切分、历史、候选、标签与评分程序 | 用户建模及排序方式 | MIND 的 AUC/MRR/NDCG；KuaiRand 的 Hit/NDCG |
| 新数据、完整下一步 | 同一原始前缀、可搜索内容环境、来源能力与资源上限 | 私有状态、查询、来源、获取次数、排序 | 本人两两选择得分，全拒绝与交付率 |
| 独立连续体验 | 同一用户的事前资料、平衡的任务与顺序、资源条件 | 每个系统独立演化的整段过程 | 本人下次使用系统的选择得分 |

研究问题是：基本推荐能力如何、完整获取与更新能否改善当前选择、整段连续使用是否更受用户偏好。分别出表，不合成一个总分。传统排序成绩解释推荐能力；新基准与真人连续体验承担完整范式的主证据。

动作格式、引用与执行成功属于运行正确性检查，工具日志用于分析收益和错误。不同合法查询、动作组合与记忆结构可以取得同样好的结果，不以匹配研究者手写的唯一动作序列作为主评分。

## 2. 目标 ID、候选与获取的边界

目标例子：用户后来点赞 `kuairand:1042`《手机跟拍足球》，内容类型 video、tag 足球。标准下一条 ID 匹配比较 `ordered_item_ids` 是否包含 `kuairand:1042`；类型、标题、tag 只作特征，不替代身份。

- **固定候选实验：**标签由评价器保管；把统一候选交给所有方法排序。按协议把目标和干扰项放在一起是测试集构造，不是提前告知哪条为正例。候选展示顺序随机，避免目标恒在第一项。
- **获取＋排序实验：**模型只能推荐实际取得的内容。库里有目标但搜漏，最终算未命中；搜到但未排入前 K，同样未命中。不能仅在“已经搜到”的样本上报告最终 Hit。
- **目录本来不含目标：**依据事前固定的目录与目标选择规则报告覆盖率，所有方法使用同一可评样本集合；不能看过系统结果再挑样本，也不为单个目标临时扩目录。
- **我们新数据的主评价：**不规定唯一正确 ID。另一条足球内容同样可被本人选中；这里评价的是当前偏好，不是是否重现旧日志。

获取诊断可报“目标进入已获取候选的比例”及“已获取时排入前 K 的比例”，但最终 Hit 分母保持全部可评样本。例如 100 题取回 80 题目标、最终推荐到 70 题，最终 Hit=70%，不能只报 70/80。

## 3. Waterfall 怎样跑传统数据

### MIND：保留原曝光排序任务

输入采用每条 impression 的历史点击 ID、关联新闻信息与该次全部候选；删除本次 0/1 点击标签。没有原始命令或明确画像就留空，记忆只能从当时可见的历史自行构建。新闻用发布包实际提供的标题、摘要等字段，不依赖今日网页内容补齐旧新闻。[官方字段](https://github.com/msnews/msnews.github.io/blob/master/assets/doc/introduction.md)

Waterfall 在固定候选模式运行，获取工具不开放到候选之外，最终 recommend 必须给出全部候选的无重复排列。适配器按原 impression 的候选顺序生成 rank 数组，调用官方 evaluate.py。评分为每个 impression 的 AUC、MRR、NDCG@5/10，再按官方方式汇总。只交 top-1 不足以完成这个评分。[官方评分代码](https://github.com/msnews/MIND/blob/master/evaluate.py)

**默认先做 MIND-small 本地可复现实验：**官方 train 按全局时间划前 80% 用于训练、后 20% 用于调参（同一时间戳不跨边界）；官方 validation 在本项目封存为本地测试。名称写明 `MIND-small / local split`，不冒充官方 hidden-test 榜单。训练字段、全局统计与已学习参数均不读取本地测试答案，测试时自己的此前可见历史仍可读。正式外部榜单比较再使用 MIND-large 官方 train/dev/test 与可用的官方提交流程；未经实际提交不报告官方测试成绩。[数据版本入口](https://msnews.github.io/)

基线至少包含训练集热度、内容相似度、NRMS 与 Waterfall；NRMS 等可在相同训练数据正常训练，Waterfall 可以使用冻结模型，分别报告训练与推理成本。所有方法跑同一个候选与评测程序。若共同抽取子集以控制大模型费用，在看标签和结果前按用户/时间固定清单，所有方法重跑该清单并以 subset 标明。

模型无效输出先记录失败；不查看标签地使用预先声明的全同分后备提交，使该题仍进入评分，并单独报告无效输出率。正常输出不得靠目标标签补全排序。

### KuaiRand：固定本文协议，使用传统指标

KuaiRand 有行为日志与普通/随机曝光，但没有唯一官方算法评测切分。下面是本项目的公开协议，不能与其他候选和切分上的论文数字直接横比。[官方数据说明](https://kuairand.com/)

| 项目 | 第一版默认设置 |
|---|---|
| 版本与切分 | KuaiRand-1K；所有用户共同训练窗 2022-04-08 至 04-21，开发窗 04-22 至 04-28，测试窗 04-29 至 05-08；使用数据 date 字段划窗、time_ms 排序 |
| 内容目录 | 训练窗已实际出现、且有可用内容元数据的视频构成固定目录 C；冻结 ID 与字段版本，不用未来点击次数/整月统计生成热度 |
| 目标定义 | 每位用户每个开发/测试窗取第一条此前未曝光、long_view=1 的视频为 target；先按此规则选目标，再检查目录覆盖，不改选更容易的目录内目标 |
| 输入与候选 | 提供目标发生前已经结束的行为及可见元数据；可评目标＋从 C 采的 100 个不同对照项，排除目标及此前正反馈项，固定随机种子并打乱位置；候选不足 101 的样本事前标记不可评并报告数量 |
| 指标与对照 | Hit@10/20、NDCG@10/20；单目标 Recall 与 Hit 相同不重复列。比较训练窗热度、内容序列相似度、SASRec 与 Waterfall；随机/普通目标分层报告 |

`long_view` 按官方时长规则，不等于人工“喜欢”。对照项未获该用户反馈时只是这个 next-item 测试的干扰项，不能写成真实点踩，也不拿它们直接算点击预测的 0 标签。推荐目录覆盖率与各原因排除数量同时报告。按全局窗口冻结训练，避免“逐用户留最后一项”时其他用户的训练记录来自测试的未来。

SASRec 的训练目标采用训练窗内 long_view 正反馈序列的下一项预测；其他原始行为作为可用记录保留，能利用它们的方法可按自身机制使用。若另做点赞任务，训练/目标统一改用 is_like，单独出表，不能一边按观看训练一边混称点赞命中。候选特征和原始历史的可访问范围对所有方法一致。

SASRec 作者实现采用留出目标与采样候选计算排名指标；我们沿用这种任务形式，但使用上面声明的时间划分和候选顺序，而不是宣称重现作者原数据结果。[作者实现](https://github.com/kang205/SASRec)

如目标时长跨越下一决策时刻，只在观看结束后把完整时长加入历史；不能用当前尚未完成的长观看标签。当前测试目标及同次结果始终由评价器保管。测试窗口中更早已经发生的行为可作为共同日志前缀，不据此宣称任一新策略真实产生了这些反馈。

### 获取能力的补充诊断

需要定位搜索能力时，另让方法在上述固定目录 C 中自行 acquire，再计算同样的目标 Hit/NDCG。这是 `local-catalog acquisition` 扩展实验；候选由方法自己取得，不能把 `target＋100 对照` 那个测试小池当搜索世界。它与固定候选实验分表。真实外网搜索也不能混入 MIND/KuaiRand 原候选成绩。

KuaiRand 点击/点赞的 AUC、LogLoss 与时长 MAE/RMSE 作为可选行为预测实验。它们需要显式的预测概率或预测时长；不能把 recommend 的名次伪装成点击概率。当前参考接口先做排名，不为凑指标增加无定义的概率输出。任务映射详见 [数据集字段与适配](dataset-fields.md)。

## 4. 新数据集怎样建

### 数据单位与内容世界

工作名 Agentic Waterfall Feed Benchmark。最小评测单位是 `用户＋截止点＋内容环境＋方法运行＋本人判断`；连续评价单位是一个指定系统的独立会话。

| 归档部分 | 保存内容 |
|---|---|
| 用户与前缀 | 去标识用户 ID、split、原话、真实行为、本人显式资料、每条信息可见时间；保留原始事件，方法自己形成记忆 |
| 可查询环境 | 内容 ID、规范 URL/来源、文本或可播放媒体/转写、类型、发布时间/可用时间、快照 hash；索引与检索器版本、来源能力、时间门控 |
| 方法运行 | 模型/提示词/适配器版本、资源配额；每次输入、原始输出、解析、工具请求和实际结果、状态版本、最终推荐 |
| 客户端结果 | 真正曝光的位置与时间、打开/阅读/播放/赞踩/收藏/评论、观察是否结束、退出或任务完成原因 |
| 私有评价 | 对比双方与内容映射、随机位置、本人选择、逐项判断、系统复用选择；隐藏目标及答案不进入当前决策 |

内容世界应能响应新查询。首版按用户选择的真实兴趣领域，从至少三种来源取得可保存快照的图文与短视频内容；来源数量是采集配置，非每次强制混源。种子主题来自试采及开发用户，另纳入通用热门与无关候选；不要只收 Waterfall 的查询结果，也不按照测试用户的隐藏答案补库。记录规模、来源/模态分布与可用率，试采后固定首版目录和规则。

首版主对比用冻结索引与内容快照保证查询机会一致；实时互联网作为独立的版本化补充批次，保存实际响应。只有旧查询缓存无法让新算法自由检索；可重放工具也不等于可以重放新策略下未知的真人行为。这一区分与 [RecSim 的交互环境设计](https://research.google/blog/recsim-a-configurable-simulation-platform-for-recommender-systems/)一致。

### 两种可复用入口

**固定池：**用独立公共检索器从原始前缀形成 20 条候选，随后请本人逐项判断“此刻愿不愿意看”，允许无法判断。这个小子集可让传统排序器直接用 Hit/NDCG 比较；候选不能来自 Waterfall 的专属结果或隐藏答案。只在逐项标签齐全的指定子集计算标准排名，未知先补标。

**完整获取：**只给原始前缀与可搜索环境；所有方法自行获取和推荐。每个方法提交 next item（主盲选）及最多 5 条后续建议（诊断）。统一工具可查更大目录，但实际允许的内容快照和字段相同。

首版逐项排名诊断只取按用户/场景预先分层抽出的 20% 前缀，避免每条都做大量标注。主盲选覆盖全部预先指定前缀；同一用户有/无指令都能参与。

## 5. 其他方法怎样接入

接口一 `rank(prefix, candidates) → ordered_item_ids`；适配器将合法排名包成 recommend。接口二 `step(observation, tools, budget) → actions`；方法可以保留自己的内存结构，公共层只转换调用、验证内容身份并记账，不替其理解用户。

| 主比较系统 | 保留原能力 | 公共适配部分 |
|---|---|---|
| Waterfall | 三类用户输入与运行环境驱动动作选择、状态更新 | 公共内容、工具与记录接口 |
| ClawRec-adapted | 事件与证据、时效状态、来源角色规划、获取、互补选择、反馈和有界补充检索 | 将浏览器/获取传输接到共同快照后端，查询与来源仍由自身决定 |
| RecBot-adapted＋公共检索 | 原话约束解析、局部合并、Planner、过滤/匹配/衰减/聚合；协同与语义路径 | 公共检索外壳给候选，原工具链决定排序；状态由自己的 Parser 生成 |
| 通用工具 Agent | 中性工具说明下自行观察、规划、查询、重试、记忆与停止 | 同一来源与动作能力，不输入 Waterfall 推断好的任务/画像 |
| 固定检索＋传统内容排序 | 固定查询/获取规则，内容或学习排序，历史特征按固定规则维护 | 无自选行动循环；完整外壳和排序器一起计时计费 |

RecBot 的协同路径若无法忠实训练，应明确 `paper-based / semantic-only` 变体，并保留其与完整版本的区别，不能拿删掉能力的版本冒称 full RecBot。[原方法](https://arxiv.org/html/2509.21317v2#S3)

MARS-adapted＋同一公共检索进入记忆与固定池排序对比分表；保留其 event/preference/profile 维护与基于自产画像的排序，不用 Waterfall 的状态替换。[MARS 方法](https://arxiv.org/html/2605.14401v2#S3)

公共检索器的第一版规则：从用户原始表达、最近原始查询、历史内容特征与本人显式兴趣构造固定查询；在共同索引做词项＋向量检索并按冻结规则融合、去重。无信号时用开发阶段固定的热榜。每次触发、来源配额和返回上限相同；规则及模型只在开发集调节。它可为 RecBot、MARS、传统 ranker 共享，不能读取 Waterfall 的私有状态或检索计划。

传统主对照优先用能对新内容打分的内容排序器；有训练标签时增加学习排序。SASRec 等 ID 模型在固定目录内正常比较；迁到开放新内容时须声明预先固定的内容回退模块，计入整套系统。不要直接把无法处理任何新 ID 的模型当唯一传统对手。

本轮查到 ClawRec 官方实现可读；RecBot/MARS 尚未核到可确认完整作者实现，现阶段按 paper-based adaptation 规划，不断言作者没有代码。原论文原设置重跑和同底座同工具适配分表；没有实际重跑就不写复现值。[ClawRec 实现与复现说明](https://github.com/RUCAIBox/ClawRec/blob/6eeb309c47430f91280e9845a98fb56a68dc0d90/docs/reproduction.md)

ClawRec-SimBench 可作外部迁移补充：只读其 input，按同一用户事件顺序维护状态，private 只给评价器；先核可用发布子集，不作为启动上述三组实验的前置条件。

## 6. 下一条盲选的具体操作与计分

同一原始前缀分别交给各系统，各自重建状态。模型输出后，展示匿名卡片，位置随机；保留真实标题、来源、类型，统一可见预览内容和预览规则。主问题是看过同规格预览后“此刻更愿意看哪个”，不是只比较标题。

主要比较 Waterfall 与四个主对手，每个前缀随机分配其中两个对手；跨每位用户的 6 个前缀使每个对手出现 3 次，双方/题目先后平衡。先按用户×方法对汇总，再跨用户报告。附加全方法多路选择时单列，不与不同对手数量的选择率混算。

`S_A = (选 A 次数＋0.5×都想看次数) / 有效对比总数（包含系统未交付）`

100 题中 58 A、32 B、6 都想看、4 都不想看，则 A=61%、B=35%、全拒绝=4%。同时公开四类回答分布。它是包含全拒绝的选择得分，不冒称排除全拒绝的传统 win rate。

- 两方法提交同一内容时只展示一次，问想看/不想看：想看作为双方同等接受各得 0.5，不想看双方 0；这类题保留在已分配两两比较的分母，并单独报告重复率与绝对接受率。
- 多路比较去重后只剩一条时，没有竞争选择，单列接受率；不得与前述两两协议的分母规则混用。
- 方法超时、空输出、查询失败属于零交付；若另一方有内容，用户可选它或都不想看，原方法不得被剔除。双方未交付记零交付、双方 0；这属于系统失败，不伪造用户说了“都不想看”。报告时区分用户全拒绝与双方零交付。
- 用户未答/无法判断单列缺失率；平台公共故障按预先规则整题重跑或整题标无效，不只重试某一方法。
- 本人判断在独立微任务区块进行，或作为该段的终止题；看到其他系统候选后不再把后续行为算作原系统独自产生的连续反馈。

双零交付等系统失败加入预分配且上下文有效的计分次数；用户主动未作答仍不填 0。有效对比总数包含“已完成有效判断＋因系统无法交付而记零的有效分配”，实现时分别存 `comparison_status` 和 `delivery_status`，避免失败被悄悄过滤。

## 7. 完整连续体验

首版主比较 Waterfall 与 ClawRec-adapted。同一参与者各用约 5 分钟，可主动提前结束；任务在分配系统前选定。例如本人确认两个相近需求“手机拍足球”和“手机拍骑车”。在用户间平衡：系统负责哪个任务、哪个先用；两种分配×两种顺序共四组。

两系统只共享事前本人确认的原始资料和指定初始历史，各自形成状态；不将第一系统的新记忆写进第二系统。每段只有一个系统，只有它实际展示的内容产生后续行为。会话中的表达、查询和点赞均自然记录，不强迫每位用户说同一句纠正话。

两段后问：**“下次要找内容，你更愿意打开哪个信息流？A / B / 都可以 / 都不愿再用。”** 用上述两两选择得分计分。它测再次使用意愿，不写成长期留存。找到信息后主动结束不算负结果。

同时报告：每次明确需求变化后到第一次用户确认愿看的内容的等待/操作数；用户自报找到足够内容或未找到退出；明确要求违反次数及曝光分母；实际延迟和费用。未完成/未接受的任务保留失败与观察时限，不能只统计成功者平均时间。

只有两个连续条件时，只报告这两个系统的差异；不能用下一条盲选推导其他系统的连续体验名次。扩展其他连续基线时新增独立分配与会话。

## 8. 采集规模、划分与执行预算

**预算草案：8 位试采＋80 位正式参与者。** 试采仅用于界面、时长、预算与方差估计；不混入正式测试。

| 部分 | 计划规模与用途 |
|---|---|
| 正式用户 | 20 位开发、60 位封存测试。若训练模型，开发用户再事前分 12 位训练、8 位验证；同一用户不跨 split |
| 下一步上下文 | 每人 6 个独立终止上下文，共 480；每个上下文两次指定方法对判断，共 960（测试 360 上下文、720 判断） |
| 连续会话 | 每人两个系统，各约 5 分钟，共 160 会话，其中测试 120；测试四种系统×任务×顺序安排各 15 人 |
| 排序诊断 | 预先按用户/场景抽 20% 上下文，共约 96 个，各 20 条公共候选逐项判断，约 1,920 个内容判断；不当作新增独立用户 |
| 模拟扩量 | 正式人类判断独立留出；模拟结果单列来源、模型及版本，不计入真人样本数 |

六个上下文分布于无历史、只有行为、明确目标、需求变化与跨会话记忆；重复类别在用户间轮换。跨会话子集分两次到访，记录间隔；本人确认的已完成任务与兴趣变化作为自然证据，不能把研究者编写故事冒充真实生活事件。任务/主题也做留出分析，避免只测相同措辞。

这些人数是预算起点，不是“已证明足够”。试采后先确定要检测的实际差异、用户级方差、所需人数与失访预留，再冻结正式 N 和停止规则；不能边看测试优势边加人或停招。参与者以有信息流使用经验、对所选场景有真实需求的成年人为起点，招募来源与覆盖范围随数据报告。实际采集前完成本人同意、去标识记录与退出处理。

**开发阶段的共同资源起点：**每次下一步任务最多 10 次实际检索/详情请求、总共返回 100 条不同候选、最多显示 5 条；所有 Agent 使用同模型版本与解码设置。每次新决策最多 32k 模型输入＋输出 token、60 秒交付截止，私有持久状态最多 8k token。原始共同前缀从最早提供的 checkpoint 顺序处理，预热消耗单列并计入总成本；不借此免费预先运行 Waterfall。

这些资源数是待试采验证的开发默认值：若不足以执行某个方法的基本机制，在开发阶段统一调整后冻结，并加一档宽松预算作敏感性比较。按真实工具子调用计费，一个封装动作内部多次检索不能只算一次。主表在共同上限下比较，不强制所有方法恰好花一样多的钱；同时报告质量—成本关系。

固定候选任务按原候选数量设置输出限制；MIND 要完整排名，不能误用 demo 每次 3 条的上限。不同模态实际给模型哪些文本、转写、画面与元数据保持同条件可访问，并披露模型能力差异。

## 9. 最小消融与统计

主对照之外，在事前固定的诊断子集运行：

| 变化 | 隔离什么 |
|---|---|
| 分别去掉原始命令、行为、显式画像 | 三种输入各自的贡献；每次从相同起点重新建状态，不残留被移除信息 |
| 固定获取 | 用公共检索器替换 Waterfall 获取策略，保留其余模块 |
| 冻结持久记忆更新 | 预热后不写新记忆，仍让最新原始事件可见；区分状态维护与单纯缺少信息 |
| 固定动作流程 | 同组件改为固定更新→获取→排序；允许反复运行但不自主选择阶段，用以检验协调机制 |

每个真人主结果先算每位用户在每个方法对上的均值，再跨用户比较；按用户成组 bootstrap 95% 区间，保留一个人的全部题与会话。预先指定 Waterfall 对 ClawRec 的两项主比较（下一条与连续体验），报告效果差和区间；多项显著性结论采用 Holm 校正。其他对手、场景与消融也报告效果与区间，不能把同一人几百次交互当几百人。

传统模型训练使用三个预先固定种子；冻结模型的随机输出可在离线测试预定子集做重复稳定性检查。真人主比较不挑“最好的一次”输出：按事前固定的单次运行/随机种子生成。测试标签不得参与提示词、参数、候选、预算或基线选择。

## 10. 模拟用户如何验证，未来方法如何加入

模拟用户只读截止点前的本人资料与经历，不读将预测的答案或未来行为。在未参与调参的真人上预测 A/B/都想看/都不想看，报告一致率、分类别效果；如输出概率再报 Brier score。比较多数选择、无画像、打乱画像基线，并用重复真人题估计本人自身判断的一致程度。

再看它是否复现各系统的选择差和排序，在冷启动、需求变化等子集及未用于校准的方法家族上检查。只有两个系统时比较差异与方向，不靠两个点的秩相关宣称充分验证。验证通过后用于明确范围内的扩量、训练和消融；论文主结论仍保留真实用户结果。

发布内容目录、原始可见前缀、统一 ID、运行器/评分器、候选清单、split、完整失败记录与训练/开发标签；封存测试答案由评测方管理。内容按可发布权限提供快照或重建清单，并记录可重建覆盖率。

**新算法入榜的两条路：**固定池直接复用已标注内容；完整获取产生新候选或新比较关系时补本人判断。可回访原参与者，但明确是新的判断时间；无法回访则用新用户真实前缀重跑全部参评方法，形成新批次，以固定参照系统连接。普通标注员不能假扮原用户产生“本人偏好”，旧赢家也不能推出两条未选内容之间的胜负。

## 11. 指标的短解释与演算

标签与指标分开：MIND 的 1/0 是点击/未点击；KuaiRand 是对应行为与时长规则；人的逐项愿看标签是另外一种标签。ClawRec 用留出下一行为的任务支持度 1–5，测试由校准后冻结的 LLM judge 评分，Hit@20 要求至少一条 ≥3；并非严格命中同一 URL。[ClawRec 指标](https://arxiv.org/html/2607.23779v1#S4.SS1.SSS2)

**Hit@K：**前 K 条至少一个正例就记 1，否则 0，再跨样本平均。100 题 70 题命中即 70%。**Recall@K：**找回正例数/全部已标正例数；4 个找到 2 个是 50%。**Precision@K：**前 K 条中正例比例；前三条有 2 个是 2/3。[标准实现](https://github.com/RUCAIBox/RecBole/blob/master/recbole/evaluator/metrics.py)

**NDCG：**当前排序得分除以同一评价范围内的理想排序得分。`DCG@K=Σ(2^标签−1)/log₂(排名+1)`。以点击标签 `[0,1,1]` 为例：DCG=`0+0.631+0.5=1.131`；理想 `[1,1,0]` 得 `1+0.631=1.631`；NDCG@3≈0.693。只有一个正例时，排第一得 1、第三得 0.5。[MIND 实现](https://github.com/msnews/MIND/blob/master/evaluate.py)

我们的二元逐项标注全部为 0 时，NDCG 记 0并报这类题比例；未知先补标。MIND 原任务使用原评分处理，不擅改官方代码后仍叫官方结果。MIND 的 MRR 是所有点击项倒数名次的均值，与某些工具只算首个正例不同。

用户仅选“最想看的一条”，不能推出其他内容都不值得看；若增加开放获取的 NDCG，应把各方法返回内容合并去重后逐项标注，使用共同理想排序并冻结评价池版本，新增内容后相应重算，不能把未判定直接算 0。[NIST 关于评价池覆盖的研究](https://www.nist.gov/publications/bias-and-limits-pooling-large-collections)

**推荐另一条足球内容：**严格历史目标 Hit 可以为 0，当前真人盲选可以胜出；两者答案不同，不能把选择得分直接改名 Hit@1。下一条偏好与完整体验偏好也分开，不用一个取代另一个。

## 12. 实施顺序与当前状态

先实现一条 MIND 曝光的输入转换、完整排名导出与官方计分；再建小型可查询内容世界，跑 8 人试采；随后冻结数据与对照，依次出传统数据、新数据盲选、连续体验三张主结果表；最后做消融与模拟扩量验证。

当前已核对字段、官方评分和近邻方法，作者示例本地回放可用；本协议的适配器、真实模型对照、数据采集、功效分析和任何效果数字尚未执行。上述数值是设计参数或演算，不是实验结果。
