# Waterfall 完整信息与数据集适配修复（2026-11-02）

这是一项会改变模型实际输入与工具流程的协议修订，不应描述成纯稳定性修复。旧结果和失败记录保留，新结果单独保存。

| 已确认的问题 | 本次改动 | 可能影响 |
|---|---|---|
| 历史初始窗口为最近 60 条，另有字节上限；查询并不保证补齐 | 正式实验首次提供全部当时可见、属于该用户的历史；Demo 推理前通过已有历史读取器读齐。查询仍可重读完整记录 | 输入长度、注意力分配与行为判断会变化 |
| 超过 100KB 自动分批，合并排序省去候选 text/abstract | 删除自动分批与合并投影；完整候选正文在每次决策中保留 | 调用次数、跨候选比较和排序可能变化 |
| KuaiRec 空查询隐式走热门，无匹配时按 ID 填充 | 只保留库内 BM25 搜索；空查询或无词项匹配返回空，不自动补候选。保留有词项匹配但 BM25 分数非正的真实结果 | 获取到的候选集合与排名会变化 |
| AgentRecBench 候选最初只有 ID，详情依赖模型是否调用工具 | 适配器在首次模型调用前读取固定 20 项官方公开详情；完整 JSON 写入候选正文。缺失数据显式标记，不捏造标题或介绍 | 模型能直接比较候选内容；强制准备读取单独计数 |

## 保留而非偷偷调整的规则

- 使用现有英文系统提示词；中文仅用于说明。此次未改模型、温度、评分、标签或目标。
- 当前每轮最多 20 次模型决策、8192 输出 token；KuaiRec/SimBench 获取上限 100。它们是既有协议边界，未在此轮增减。
- 上轮增加的 20 次工具额度实际上是通用额度，不是历史专用。此次暂时保留：AgentRecBench 42、KuaiRec/SimBench 30、KuaiRand 20。
- AgentRecBench 强制读取的 20 次候选详情计入 preparation_tool_calls；total_tool_calls 为准备读取加 Agent 的实际调用。用户资料和历史评论仍由 Agent 经原工具读取。
- 保留执行前参数校验及同一轮内纠错；这可能增加模型调用、改变后续决策。它不会替模型选择候选或排名，也不会从多个有效答案中择优。
- 保留已有瞬时服务错误重试及队列的基础设施失败恢复；所有付费尝试均留存。真实工具异常、无有效交付或不适用的服务错误仍使复验停下。
- 隐藏目标、未来事件与其他用户的私有历史仍隔离。“不省略”指完整合法可见输入，不是把评测答案交给模型。
- 单次检索返回数量、最终 Top K、固定候选全集排序要求仍遵循各数据集原协议。

## 证据边界

此前 80 条复验中，17 条触发过自动分批（SimBench 16、KuaiRand 1）；25 条 KuaiRec 和 5 条 KuaiRand 的初始历史超过 60 条。这些不是“信息完整”的证据。

本轮固定 29 条原有样本：KuaiRec 开发集 20、AgentRecBench 三领域各 1、KuaiRand 原分批案例 1、SimBench 同一用户连续 5 事件。选择在新答案生成前冻结。全量实验不自动启动。

已存在的基线 512-token 查询截断问题未在本轮修改；不同方法预算、适用样本及旧输入协议尚不能据此宣称完全公平。新旧 KuaiRec 获取协议不同，前后分数只能作诊断，不是单因素因果结论。
