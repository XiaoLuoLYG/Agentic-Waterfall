# Waterfall Anything 独立仓库与 Hive 模块迁移设计

状态：用户已于 2026-10-14 确认并授权直接执行。实现与验证进度见 implementation-plan.md 和 validation.md。

## 目标与已确认事项

建立私有仓库 `XiaoLuoLYG/waterfall-anything`，保留三个长期分支：`rust`（默认）、`hos`、`release`。Waterfall 从 DigitalMate 中独立出来，既能作为专用 App 运行，也能放入 HyperAgent 的 Hive。用户已确认首版采用**编译时插拔**，以后通过同一宿主接口替换为 Rust 实现。

Rust 本次不迁移、不重写；不创建假实现。原 DigitalMate 与 HyperAgent 源仓库只作为参照，不改动它们的业务实现。本次也不发布应用商店版本、不部署新后端。

## 为什么不能直接复制一个文件夹

DigitalMate 的 Waterfall 分布在 `agent_core`、页面内的 `waterfall`、HTML 渲染器和 Worker 中。按相关路径初筛有 47 个生产 ETS 文件，尚不包含完整的间接依赖和页面内嵌逻辑；这不是最终迁移文件数。

主要耦合证据（均基于上述 DigitalMate 提交）：

| 位置 | 当前耦合 | 迁移处理 |
| --- | --- | --- |
| `entry/src/main/ets/pages/A2uiHome/Index.ets` | 13,352 行主页面中混有 Waterfall 会话、调度、反馈、模型调用及大量其他业务 | 抽取 Waterfall 控制逻辑；不复制整个主页面 |
| `Index.ets:8014` 的 `submitWaterfallConversation` | 在 8030 行执行 `restoreAccountSession()` | 独立 App 不要求 DM 登录；模型可用性由宿主配置决定 |
| `waterfall/DiscoveryMemoryProjectionCoordinator.ets:1` | 直接依赖 DM 记忆运行时和存储 | 保留偏好投影能力；记忆输入由宿主提供，独立 App 可不提供 |
| `agent_core/.../AggregateSearchClient.ets` | 搜索连接多个来源客户端及通用 `ComposioDynamicBackend` | 按实际来源调用拆出必要适配器，保留鉴权、分页和错误处理，不带入整套业务工具注册表 |
| `waterfall/WaterfallShareService.ets:7` | 分享后端地址硬编码 | 改为配置；未配置时使用现有可用的分享回退行为 |
| `waterfall/WaterfallPoolWorkerClient.ets:382` | 负责持久化关闭、未完成请求失败处理及 Worker 终止 | 迁移时保留完整的退出处理，并验证新打包路径 |
| `html/HtmlAggregateSearchHomeRenderer.ets` | 已承载 Waterfall 卡片、阅读、来源设置等 UI | 保留其界面和行为，只抽取需要的类型、图标及 WebView 桥接 |

HyperAgent 当前是精简聊天 App；聊天页仍依赖 `libjiuwenrust_napi.so`。独立 Waterfall 首版不需要这个聊天入口和原生模型库，不能直接保留其整个依赖清单。

## 方案选择

1. **推荐：先抽独立 ETS 模块，再接最小 App。** 保留现有算法与 UI，把宿主依赖集中到接入处。迁移需要整理主页面中的控制逻辑，但符合 Hive 插拔目标。
2. 复制 DM 后删除业务。启动较快，但很容易继续依赖 DM 页面状态、账号和通用工具系统，后续仍需再次拆分。
3. 现在同时用 Rust 重写。变更与验证范围明显扩大，也不符合本次“Rust 暂不迁移”的要求。

## 三个分支的内容

| 分支 | 本次交付 | 明确不做 |
| --- | --- | --- |
| `rust`（默认） | 项目说明、来源提交、三分支用途、已验证的模块接入约定、Rust 后续重写范围 | 不放 ETS 实现，不创建占位 Rust 算法，不宣称可运行 |
| `hos` | 独立 Waterfall ETS 模块、必要来源/平台适配器、相关测试与接入说明 | 不放 DM 整体产品及完整业务工具系统，不承担 App 签名发布 |

`hos` 的模块根采用 `hive/waterfall/`；`release` 把同一内容放到 `entry/src/main/hive/waterfall/`。用明确的源提交与文件一致性检查管理同步，不跨分支混入 App 壳，也不引入子模块或额外长期分支。迁移过程中可使用临时开发分支，最终长期分支只保留上述三个。

## 模块内部与宿主职责

模块内部按现有职责收拢：核心类型与排序、内容池与批次调度、来源适配、偏好与库存存储、Worker、UI 与 WebView 桥接。目录拆分以现有代码为准，不新建通用插件框架。

宿主负责提供：模型能力和配置、应用存储上下文、需要凭据的来源连接配置，以及可选的外部记忆输入。平台行为如外部打开、语音、系统分享由 HarmonyOS 接入层处理，核心排序不反向引用 App 页面。

模块接入约定覆盖以下能力；具体 ETS 类型在实施计划中依照现有类型收敛，不先设计一套平行数据模型：

- 创建模块并装配宿主配置，挂载 Waterfall 页面。
- 分别开启兴趣推荐或关键词搜索；两种会话保留独立状态。
- 更新显式偏好和来源选择，接收内容和状态更新。
- 进入后台时落盘，退出时停止任务、拒绝未完成请求并释放 Worker/监听。

拔出模块后，宿主移除模块注册、页面引用与专用 Worker 打包入口即可编译；宿主不需要了解 Waterfall 的内部类型。首版不做远程下载插件、热更新或者动态安装。

Rust 后续优先替换内容处理与调度实现；HarmonyOS UI、语音和系统分享仍留在平台接入层。Rust 与 ETS 的桥接机制届时再选，本次不提前引入 FFI 或原生库。

## 保留与移除的功能

保留现有 Waterfall 的两种入口：兴趣推荐和关键词搜索。保留内容召回、分页进度、去重与排序、P/S/E 相关调度、补充内容、库存恢复、偏好标签、行为反馈、收藏/喜欢、来源选择、RSS、内容阅读与媒体播放、评论、分享、语音偏好输入和阅读相关 AI 能力。

来源适配器以当前实现为迁移基准，不为缩小仓库擅自删掉某个平台。需要外部服务或凭据的来源保留可配置接入；无配置或服务失败必须表现为真实不可用状态，不能用示例内容替代。

当前独立 App 尚未包含 DM 主聊天与任务执行宿主、日历/邮件/出行等业务工具。用户于 2026-10-14 明确补充：必须保留任务执行与内容发现互补的体验，不能把内容 Worker 当作任务执行。恢复方向是由宿主执行任务，Waterfall 展示原版任务卡、进度、结果与追问；具体工具范围及是否要求桌面/锁屏后台继续执行正在确认，尚未实现或验收。

不复制 DM 的个人数据、签名材料或无关账户配置。用户后续明确授权复用 Waterfall 相关模型和来源凭据，只导入本地调试配置和新应用，不提交 Git。新的 App 使用独立应用身份；建议包名 `com.xiaoluolyg.waterfallanything`，后续签名必须与该身份匹配。

## 具体行为例子

- **打开 App：** 直接进入 Waterfall 推荐页；无需先登录 DM 或经过聊天首页。
- **输入“少看游戏，多看摄影”：** 仍走现有偏好解析、标签更新和内容调度；模型从本 App 配置读取。
- **关键词搜索后内容耗尽：** 保持搜索会话及现有耗尽行为，不自动改成兴趣推荐。
- **宿主没有外部记忆库：** Waterfall 仍使用自己的标签、偏好和行为记录；以后嵌入 HyperAgent 时可由宿主补充偏好投影。
- **退出页面或 App 转后台：** 保留现有库存落盘和错误处理，迟到的异步结果不写入已经结束的会话。
- **编译时拔出：** 移除接入项后，宿主仍能构建；不要求携带 Waterfall 的来源凭据或模型依赖。

## 验收要求

1. 远端仓库为私有；长期分支为 `rust`、`hos`、`release`，默认分支确认为 `rust`。
2. `hos` 可在独立测试工程中验证；依赖检查不能出现回指原 DM 工作区、整包 `@loop/agent-core` 或 DM 业务目录。
3. 迁移并运行与本次范围直接相关的已有测试；新增接入接口、持久化退出和模块接入/移除的必要检查。记录真实结果，不沿用旧仓库的历史测试通过数。
4. `release` 的模块内容能追溯到 `hos` 的确定提交，保持文件一致性。
5. 验证推荐、搜索、偏好修改、收藏/反馈、重启恢复及失败状态；保留现有 Worker 调度和可见内容稳定性，避免为了拆分改动排名策略。
6. 执行 HarmonyOS 构建并产出可核验的 HAP/APP 构建物。没有匹配签名时明确标记为未签名；构建成功不等同于设备功能验收或商店发布。
7. 用最小宿主验证模块可接入、可移除；记录 Worker 路径和资源路径约束。原 HyperAgent 上游的实际业务集成属于后续独立改动。
